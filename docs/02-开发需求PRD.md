## 1. 产品定义

**面向持续阅读、记录、研究和表达的中国社交媒体创作者，连接 IP 经营、素材与知识、选题决策、Agent 创作、作品管理、审核交接、人工记录与 AI 复盘的 Web 工作台。**

产品的持续价值是：知道资料在哪里、知道今天为何值得写、让作品可持续修改和交付、知道发布后发生了什么，并把这些经验带回下一轮。

用户输入中的 DraPub 用作远程草稿、审核及渠道工作流的能力参考，名称与服务复用均未确定。本项目正式名称为“Loretide”，GitHub 仓库名为 loretide。已确认范围适用于所有开发阶段：仅中国社交媒体；人工发布和记录真实结果，AI 处理复盘；不接入平台直接发布。

用户已确认以 Multica 为源码底座，复用基础平台并直接增加 Web 页面和 Go 业务服务。AI 供应商和 Agent 框架可替换；OpenClaw 依赖、安装/执行分支、兼容层及旧路径全部移除。Pi、OpenCode、Codex、Claude Code、Hermes 已有上游后端可研究复用，Gemini CLI 和完整 API 任务执行器需补开发；全部路径仍须按 R-030 验收。代码证据见 [08 研究报告](08-Multica源码研究与小改可行性.md)，当前决定见 [09 开发映射](09-Multica二次开发决策与模块映射.md)。

### 1.1 产品功能的实现归属

| 实现方式 | 范围 | 产品约束 |
|---|---|---|
| 复用 Multica | Workspace、成员权限、Project、Issue/Task、运行与 daemon | 保持既有身份和任务体系；工作目录不等于安全沙箱 |
| 新增内容业务模块 | IP、来源知识、选题、作品/版本、审核交接、人工发布/指标、复盘与经营记忆 | 原生页面与 Go 服务管理专用数据，作品状态与任务状态分开 |
| Skill | 选题判断、对标、整理、事实核查、多平台创作、AI 复盘 | 定义工作方法和输出格式；不能代替数据库、正式编辑器和服务端权限 |
| 可选插件 | 素材侧栏、IP 摘要、审核辅助面板 | 非 P0 依赖；关闭或卸载不丢失正式资产、不阻断人工流程和 AI 结果入库 |

本次调整实现路线，不改变 R-001～R-055、NFR-01～NFR-10 的 ID 和分期。R-031～R-048 的正式作品、人工记录和复盘由内容业务模块承担；R-025～R-030 的 Skill 输出必须校验后入库；R-052～R-055 的 API/MCP 与平台插件是不同接入方式。插件本身不构成权限授权，现有插件宿主借用用户会话也不能据此认定一次操作是人类明确确认。

## 2. 用户、问题与成功结果

| 用户问题 | 产品能力 | 用户可感知的成功结果 |
|---|---|---|
| 素材分散，想用时找不到 | 收件箱、来源快照、搜索、知识卡、素材包 | 找到原文、批注及曾经用过它的作品 |
| 参数、评价、竞品反复整理 | 有依据的整理、对标矩阵、实体属性与事实核查 | 一次研究可被多个选题和渠道复用 |
| 有素材却不知道今天该写什么 | 账号表达配置、内容支柱、选题理由、投入与证据评估 | 能选择今天最值得推进的一项工作 |
| 各平台反复重写且版本混乱 | 作品容器、渠道版本、可编辑文档、差异与采用 | 同一研究派生多个独立可追溯的渠道稿件 |
| 图文和视频前期制作零散 | 图文逐页文案、口播、分镜、字幕、拍摄清单、附件清单 | 从一份简报获得一致的制作交接包 |
| 审核、排期、反馈不连贯 | 版本审核、日历、交接单、人工记录与 AI 复盘 | 从选题追到实际发布，并找到后续经验依据 |
| 已用本地 Agent，不想重建工作方式 | 服务 API、Skill/桥接、MCP 接入 | 外部 Agent 的成果出现在同一作品库与审核队列 |

### 2.1 人群与角色

首要人群：经营品牌官方、相关人设及其他账号矩阵的内容运营者；角色、内容重点与运营目标由用户在 App 内定义，这些账号类别不是硬编码角色。

首版一个用户可承担全部角色；角色语义保留，团队权限后续展开。

| 角色 | 主要动作 | 首版落实方式 |
|---|---|---|
| 拥有者 / 创作者 | 维护档案、选题、写作、采用、管理集成 | 个人账号默认拥有 |
| 审核者 | 查看交付快照、处置问题、通过或退回 | 本人完成，保存人工动作 |
| 运营者 | 排期、交接、登记发布和反馈 | 本人完成 |
| Agent 身份 | 读取指定上下文、研究、创建候选作品、提交审核请求 | 独立受限凭据，不能人工批准或代填真实数据 |
| 协作者 / 访客 | 后续分工、评论、限定查看 | P1；首版不展示未实现入口 |

## 3. 目标、指标与范围

### 3.1 北极星指标

**滚动 28 天内完成“实际发布登记 + 至少一次真实反馈记录 + 已生成 AI 复盘”的不同作品数。**

同一作品多个渠道不重复计为多件作品；渠道产出另计。只有自报发布而缺少可核查依据的记录单列展示，不能混称已核验成果；复盘是否被查看、结论是否被采纳另外统计。这个指标衡量经营闭环，不能代表商业收益或内容质量。

### 3.2 辅助指标

| 维度 | 指标定义 | 采集方式 |
|---|---|---|
| 素材复用 | 周内被简报/作品引用的不同知识卡数 ÷ 已确认知识卡数 | 系统引用关系；分母为 0 显示暂无 |
| 创作效率 | 简报确认到首次采用的耗时中位数 | 系统动作时间；人工记录活跃工时另列 |
| 建议有效性 | 建议选题进入简报的比例及暂缓原因 | 系统事件；不以提升采用率牺牲自主选择 |
| 交付稳定性 | 到期计划中按时完成交接或发布的比例 | 区分交接准时率和实际发布准时率 |
| 反馈完整性 | 达到指定观察时间且已录入观测的发布记录比例 | 人工观测 + 时间规则 |
| 证据质量 | 已审核交付中未处置关键事实问题数 | 应为 0；不声称内容绝对正确 |
| 成本 | 每次运行、每个采用版本的模型与工具实际成本 | 提供方可用账单/用量；不可得时标记未知 |

增长、粉丝和转化指标由用户根据真实渠道数据选择。不同平台及不同观察窗口分别展示。以上均为拟实现指标，本轮没有基线或验证结果。

### 3.3 分期定义

- **P0 / 首版必需：** 能完成一次从材料接入到真实反馈进入下一轮选题的完整闭环，且作品和权限可信。
- **P1 / 增强：** 提高接入广度与协作效率，包括远程 MCP、团队、资料连接器、渠道导出格式和媒体连接器。
- **P2 / 扩展：** 跨品牌集中管理、商业计费、高阶实验分析、复杂媒体制作等。

具体 P1 能力是本产品完整规划的一部分。未通过能力验证前不在界面标成“已支持”。

### 3.4 当前默认假设

| 决策 | 本稿采用值 | 状态与影响 |
|---|---|---|
| 首要用户 | 品牌内容运营，单人可完成，预留小团队 | 最新确认 |
| 工作区与 IP | 一个品牌一个隔离工作区，内部多个账号、人设、项目与 SOP | 多账号及账号人设提示词属于首版模型 |
| 部署 | 同一服务支持本机或用户管理的服务器；首个验收环境使用单实例 | 设计建议；公网服务方式与费用待后续选定 |
| 平台范围 | 仅中国社交媒体内容创作 | 用户已确认；全阶段适用 |
| 初始渠道 | 微信公众号、小红书、抖音、视频号；各有独立稿件和交接包 | 本稿设计建议；具体首发组合可调整 |
| 发布 | 工作台审核、导出与提醒；运营者在各平台手动发布并登记 | 用户已确认；平台直连发布排除在各阶段范围外 |
| 真实反馈 | 人工表单和 CSV 导入为首版正式路径 | 用户明确要求人工收集 |
| 复盘 | AI 读取人工记录生成分析、限制与下一轮建议 | 用户最后明确；用户可编辑和采纳成果 |
| 模型执行 | 统一执行接口支持 Pi、OpenCode、Codex、Claude Code、Gemini、Hermes 和模型 API；执行器与模型连接分别配置 | 不固定默认框架；每条交付路径及其隔离策略独立验收 |
| 技术栈和包版本 | 本稿给架构约束及候选组合，实现前锁定 | 尚未安装依赖或创建代码 |

### 3.5 首版不纳入的开发项

平台直连发布、向平台草稿箱写入、平台自动排期与代发送不在本产品范围内。其他首版不纳入项：商业 SaaS 计费、多客户代运营、绕过限制抓取、全量双向笔记同步、自动训练模型、全自动反馈抓取、实时多人协同编辑和完整视频剪辑器。

## 4. 领域对象与术语

后续可按需要增加知乎、B站、快手、微博、今日头条等中国平台模板。默认正文语言为简体中文，外文来源可用于研究并保留译文对应；邮件营销与海外社媒分发不纳入产品范围。来源语言与目标渠道是两个独立字段。

| 对象 | 含义 | 关键区别 |
|---|---|---|
| 工作区 Workspace | 权限、资料和运行的归属范围 | 与一个内容项目分开 |
| 账号表达配置 AccountConfig | 受众、定位、内容支柱、风格、经营目标 | 修改产生版本，不覆盖历史上下文 |
| 来源 Source / 快照 SourceSnapshot | 被采集的对象及其某次实际内容 | 相同 URL 可有多个快照 |
| 知识卡 KnowledgeCard | 经整理的事实、引文、观点、方法或案例 | 可多源支持；摘要不自动成为事实 |
| 素材包 MaterialPack | 为某一问题整理的一组材料、证据与缺口 | 有来源版本清单，可供多次创作使用 |
| 选题 Topic | 一个尚可选择、暂缓或放弃的表达机会 | 选题被保存不等于开始创作 |
| 简报 ContentBrief | 一次创作的目标、范围、交付物和约束 | 运行引用确定版本 |
| 作品 Work | 同一创作意图下的长期资产容器 | 可包含研究稿、正文和多种渠道稿件 |
| 文档 Artifact | 可独立编辑的正文、研究报告、脚本等成果 | 有 working copy 和不可变 revision |
| 版本 ContentRevision | 某个文档在一个确定时刻的内容快照 | generated、adopted、approved 是不同动作语义 |
| 渠道稿件 ChannelVariant | 作品在某渠道及内容形态的表达分支 | 各自审核、交付和记录结果 |
| 审核 ReviewRequest / Decision | 人对具体交付快照的结论 | 不授予任意未来版本发布权限 |
| 交付任务 DeliveryJob | 已审核内容包的导出、人工交接与计划提醒 | 导出成功不代表已经手动发布 |
| 发布记录 PublicationRecord | 某个平台实际发布行为的登记 | 标明声明、证据、核验和版本匹配程度 |
| 观测 MetricObservation / FeedbackItem | 人工记录的指标、评论、线索 | 与 AI 分析分别保存 |
| 复盘 Retrospective / 经营结论 Learning | AI 基于人工真实记录生成报告与结论；采纳后形成长期经验 | 分析有输入版本、依据、适用范围和撤回机制 |
| 内容项目 Project | 系列、活动或周期性目标的组织单元 | 个人可使用；成员协作后续增加 |

详细配置、隔离与切换契约见 [核心架构决定](07-隔离工作空间与可替换AI执行架构.md)。

## 6. 选题判断规则

首版采用可解释维度与规则，不对未来流量作保证。排序可内部计算，前台以理由、依据和缺口为主。

| 维度 | 使用的实际输入 | 输出 |
|---|---|---|
| 受众相关 | 档案问题、已确认反馈、用户指定方向 | 高/中/低与关联问题 |
| IP 一致性 | 内容支柱、经验范围、表达边界 | 适配说明或偏离提醒 |
| 证据准备度 | 来源是否可读、关键论断是否有支持 | 可开始 / 需补证 / 暂不足 |
| 当下价值 | 原文事件时间、计划节点、持续问题 | 时效窗口或常青价值 |
| 新意与复用 | 近期作品、素材复用、旧稿新信息 | 新角度 / 更新 / 重复风险 |
| 投入匹配 | 制作形式、用户时长预算、缺失资料 | 估计区间和估计依据 |
| 历史参考 | 可比较的真实观测和已确认结论 | 参考样本及不可比较因素 |

缺失维度标为 unknown，不补成中等分数。重要依据缺失时，不显示综合“高置信度”。用户始终可以选择低排名或全新选题。避免一直推荐同类高表现题材，允许探索比例与内容支柱覆盖规则。

桌面优先；移动端至少支持速记、查看作品、轻量审阅和反馈录入。首版侧栏控制在以下主要入口，IP 和集成放在设置区域。

| 页面 | 用户主要任务 | 关键内容与动作 |
|---|---|---|

| 收件箱 | 保存和分拣材料 | 输入预览、解析状态、批注、标签、归档、知识卡候选 |
| 知识库 | 找资料和组成素材包 | 中文搜索、卡片、来源侧栏、引用去向、支持/冲突与素材包 |
| 选题 | 管理机会与简报 | 候选列表、选择理由、阶段、简报及补证待办 |

全局提供快速采集和搜索。审核可通过作品页筛选与今日待办到达，避免为个人模式制造过多菜单。项目归作品页组织，不与 Workspace/IP 混用。

作品详情的主区域始终是当前成果；Agent 面板为辅助区域。执行进度不能取代正文。用户关闭 Agent 面板后仍可完成主要编辑和审核流程。

所有异步操作显示排队、运行、等待用户、成功、失败和重试入口。重要空状态提供下一步：添加素材、补充档案、连接执行方或开始人工创作。

## 8. 权限与业务不变量

1. 每个来源、作品、任务与查询都受工作区权限限制；仅隐藏页面不能实现权限控制。
2. 原始来源、用户判断、AI 摘要、真实观测、AI 推断分别建模，不能互相伪装。
3. 用户编辑和 Agent 输出都落入文档对象；原文、已审核版本与发布快照不可被静默覆盖。
4. 审核批准固定交付快照；新版本和新附件必须有自己的审核决策。
5. 采用、人工审核、排期提醒、实际发布记录分别保存；个人界面可合并操作步骤但不合并含义。
6. Agent 使用授权资料与工具，不能从资料文本获得额外权限，不能自动批准自己的作品。
7. 每个渠道有独立交接及手动发布记录；某渠道失败不改变其他渠道的已登记结果。
8. 人工指标缺失为 unknown/null，确认的零值为 0；更正追加记录，不悄悄覆盖原始观测。
9. 复盘由 AI 处理，输出和人工原始记录分别保存；未采纳分析可作临时建议，采纳后进入长期经营记忆，历史输入可回放。
10. 人工发布结果不明时保持待登记/未知；内部导出、运行和记录写入支持幂等，避免重复成果。

## 11. 首版完成定义

用户可以导入自己的少量材料，维护 账号表达配置，查看有依据的选题，创建简报，经一个真实执行方完成研究和草稿，人工编辑与采用，生成至少两个渠道版本，完成审核及交接；用户在平台手动发布，手工录入发布结果和真实反馈；AI 根据这些记录生成复盘与下一轮建议，并展示原始依据。用户可以编辑报告，或采纳一条结论作为长期经营记忆。

同时，一个外部 Agent 能通过受限 API/桥接提交同一作品系统中的候选版本；它无法替用户批准审核或将自生成数字登记为真实指标。测试数据演练与真实使用验收分别留证据。

首版以人工发布的经营闭环验收；按钮数量、生成篇数或测试桩运行成功不能替代作品编辑、人工审核及真实反馈的流程证据。

本轮已将品牌空间、账号授权、账号提示词、受约束 SOP、风险处置和浏览器测试决定同步到主工作流、PRD、技术与验收。仍为开发规格，不表示应用已实现。审核细节以 [审核内核计划](10-审核内核合并与精简计划.md) 为专项契约；相同输入快照在所有入口使用相同后端规则。

已确认新建品牌空间的自动预检默认开启，提审时触发，关闭后保留手动检查。首版所有账号统一使用品牌级开关，不提供账号级覆盖；最终人工审核不可关闭。首版媒体边界已确认：文字、图文文案和视频脚本在工作台内创作；图片与视频成片在外部制作后放入已授权的本地工作/素材文件夹，由工作台登记引用，作为正式作品附件支持预览、版本绑定及人工终审，替换附件后重新审核。首版不要求内置排版、剪辑、媒体生成或成片自动审核；AI 必须区分文字已检查与媒体未检查，不能以脚本检查代替成片审核。
