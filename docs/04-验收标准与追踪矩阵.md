# Loretide · 验收标准与追踪矩阵

版本：v0.6.0 · Multica 二次开发方案（中国社交媒体范围）  
日期：2026-09-12  
关联：[PRD](02-开发需求PRD.md) · [技术设计与工作包](03-技术设计与开发路线.md) · [工作流](01-完整工作流.md)

**当前状态：以下均为待开发验收标准，尚未执行应用测试。** 本轮只生成和核对需求文档，不把设计、模拟样例或历史项目测试当成当前功能。

最终范围：仅中国社交媒体内容创作，面向品牌内容运营、支持单人并预留小团队；**运营者手动发布，手动录入发布结果与真实反馈；AI 完成复盘。** 平台直连发布、平台草稿写入、平台自动排期和代发送都不属于开发范围。

当前以 Multica 为底座，原生内容业务模块承担正式资产与状态，Skill 指导 AI，插件按需使用。验收对象是独立实施工程，不能用研究源码、SDK 存在或上游历史测试作为通过证据。彻底移除 OpenClaw 运行依赖与兼容入口；新增 Gemini CLI/完整 API 路径和已有后端逐项验证；官方 CLI 调用不等于满足认证/文件隔离要求。当前源码差异见 [08 研究](08-Multica源码研究与小改可行性.md)，实施决定见 [09 映射](09-Multica二次开发决策与模块映射.md)。

## 1. 验收方法与证据

| 方法 | 用途 | 有效证据 |
|---|---|---|
| 合同测试 | 类型、鉴权、scope、适配器、幂等和错误 | 当前提交/构建下的命令、退出码、报告 |
| 集成测试 | 真实数据库、版本、事务、恢复 | 输入夹具、状态变化、持久化结果、重启后读取 |
| 浏览器验收 | 实际页面和人的完整操作 | 页面/步骤、截图或录屏、对应对象 ID 与版本 |
| 实际执行方验收 | Provider 与外部 Agent 可真正完成工作 | 提供方/客户端版本、运行 ID、实际输出与 Web 入库证据 |
| 真实用户闭环 | 实际素材、人工发布、记录与 AI 复盘 | 用户手动发布后的链接/证据、人工数据和 AI 报告关联 |

测试 fixture 必须标记 `demo`。真实用户资料由用户选择用于验收；平台操作由人完成。只有真实记录不为空且来源有说明时，才可计入真实经营数据；不能凭测试脚本生成一条记录就声称已真实发布。

## 2. 功能验收与需求追踪

AC-001～AC-055 与 R-001～R-055 一一对应。P0 为首版必过；P1 在相应增强能力进入开发时验收。每项失败都应有可重现输入、实际结果和预期差异。

## 4. 六条端到端场景

### E2E-01：完整内容经营闭环

1. 创建 账号表达配置，选择受众、两项内容支柱与两个渠道。
2. 导入一篇网页、一个 Markdown 文件和一段转录，确认知识卡并组成素材包。
3. 在今日页选择有依据的选题，确定简报。
4. Agent 生成研究、对标、事实清单和草稿；创作者编辑、比较版本并采用。
5. 派生两个渠道稿，人工审核通过，导出待发布包并安排提醒。
6. **用户到平台手动发布**；开发测试阶段仅用标记 demo 的模拟登记，不能当作真实发布。
7. 运营者手工登记发布链接、实际时间、标题差异和真实反馈记录。
8. AI 根据这些记录生成复盘，报告链接到输入记录和实际稿件版本。
9. 下一轮选题展示该分析及限制；选择采纳一条结论后能从长期经营记忆中检索。

通过条件：以上路径在 Web 内可连续操作，所有产物和关系持久化；平台上的实际发布由人执行；报告不修改人工原始数据。

### E2E-02：人工记录 + AI 分析的严格分工

使用明确标识 demo 的观测：某渠道 24 小时阅读 1,000、收藏 80；另一个渠道 7 天播放 2,000；另有一项指标缺失。AI 可说明该渠道该窗口的收藏/阅读比为 8%，前提是字典确认该比率有意义；不能把另一平台播放直接并入阅读，也不能填补缺失项。

用一条虚构评论测试脱敏摘录与运营者解释的区别。AI 必须将评论作为个例反馈，不能推出整体受众百分比。报告的每个关键数字都能追到人工输入。

### E2E-03：改稿、审核与排期

审核 a2 后排期；创建候选 a3 不改动旧快照。选 a3 为交付目标后进入 held，新版未审核无法取“已审核包”。选择继续使用 a2 时明确预览其版本。只改计划时间更新提醒，不更改内容审核。

人工在平台改成 a2' 后，发布记录保存差异；AI 复盘不把 a3 误当实际发布内容。

### E2E-04：外部 Agent 接入

为一个实际客户端配置限权 Key/桥接，从授权资料生成候选文档，Web 编辑和审核可用。尝试将请求体 `author_kind` 改为 human、请求其他工作区资料、填写人工指标或通过审核，必须拒绝。吊销后新请求失败。

这个验收不涉及本机任意文件读取、不假设客户端订阅能被服务端调用，也不包括平台发布工具。

### E2E-05：失败与恢复

模拟解析失败、模型中断、浏览器断网、Worker 重启和重复点击导出。检查原件、人工草稿、成功阶段结果、待补数据和导出版本都不丢失。真实记录保存后 AI 失败，恢复模型可重新分析同一输入。

### E2E-06：数据更正和复盘版本

先由 AI 分析观测 m1，再由人更正为 m2。旧报告 r1 保留 m1 输入；界面提示分析已过期，新运行生成 r2 引用 m2。撤回一条已采纳结论后，新的推荐不继续将其当稳定依据；历史推荐仍能解释当时为何使用。

上述 AC-001、AC-030、AC-103 的具体执行场景见 [隔离与切换验收映射](07-隔离工作空间与可替换AI执行架构.md)。所有计划交付的适配器逐项记录，不能用一个路径通过代表全部通过。

## 5. 关键失败必须如何呈现

| 失败 | UI 必须说清楚 | 恢复路径 |
|---|---|---|
| 资料没解析出来 | 哪个文件、保留了什么、失败原因 | 手工粘贴/上传可读版/重试 |
| 没有足够选题依据 | 缺什么、当前只凭哪些输入 | 补资料/自建选题/接受有限范围 |
| AI 改写与人工编辑冲突 | 两边基于哪个版本 | 比较、部分采用、保存分支 |
| 事实问题未处置 | 论断、证据和影响 | 补证、删去或明确改为假设再核查 |
| 审核后换稿 | 新旧快照与已排期版本 | 重审新稿/继续旧版/取消计划 |
| 已导出但没有发布登记 | 已交接、实际发布未知 | 人工登记/延后/取消 |
| 手工指标口径不一致 | 平台、单位、窗口差异 | 修正映射或分开展示 |
| AI 复盘无输入或失败 | 缺记录或运行失败；不编造分析 | 补录后生成/重试 |
| 记录更正导致旧分析失效 | 哪条观测变化、影响哪份报告 | 生成新版复盘 |
