## 3. 确定的改造方向

### 3.1 延续现有工程

前端沿用 React/TypeScript/Vite，后端沿用 Python/FastAPI/Pydantic。执行层从现有 Hermes 路径抽取为通用接口，Agent 框架与模型 API 均可驱动业务流程。客户端自行认证，API 密钥由受信连接器按空间授权管理；不跨框架转交登录令牌。最新决定见 [隔离工作空间与可替换 AI 架构](07-隔离工作空间与可替换AI执行架构.md)。

Web、CLI 和外部 Agent 最终调用同一套工作台领域服务。已有 HTTP 路由按兼容需要保留；新业务 API 使用版本化契约，避免同名路由的语义悄然变化。结构化 DTO 以 Python/Pydantic 与 OpenAPI 为契约，前端生成或校验对应类型。

PostgreSQL 仍是本项目新增业务事务层的设计选择，用于来源、作品版本、审核、人工观测和任务；它不是当前仓库已存在的实现。新增 Worker 使用 Python。Hermes 会话数据库由 Hermes 管理，本项目不直接修改其内部数据库，也不把会话历史当正式作品库。

### 3.2 首批需要适配的能力

| 改造项 | 保留的价值 | 必须补齐的部分 | 关联需求 |
|---|---|---|---|
| 今日页、想法、热点和日历 | 导航、页面组织、已有交互 | 按真实素材、IP 和人工反馈解释推荐；日历只做计划与提醒 | R-008、R-020～R-024、R-041 |
| 画像与知识 | 画像文件结构、内容技能与材料入口 | 版本化来源、知识卡、素材包、确认状态和检索证据；档案更新需采用 | R-005～R-019 |
| 内容输出 | 输出目录和预览 | Work、Artifact、WorkingCopy、Revision、差异和部分采用；AI 输出入正式作品 | R-031～R-036 |
| 审核和交接 | 原有发布中心的预览组织可以参考 | 改为渠道稿最终快照审核、复制/下载和人工登记；停用真实发布执行路径 | R-038～R-043 |
| 反馈与记忆 | 分析任务和画像关联方式 | 原始数据仅人工写入；选定执行器输出独立 AI 复盘；采纳后写长期结论 | R-044～R-048 |
| 外部 Agent | Hermes 内置执行链与现有 API | 增加限权服务 API、结果提交、Skill/stdio 桥接；远程 MCP 后续独立验证 | R-052～R-055 |

### 3.3 人工发布边界要落实到执行层

源码可见 /api/publish/{platform}、平台登录和 /api/analytics/{platform} 等入口。目标产品需要停用平台登录、平台草稿写入、发布、平台排期和自己的运营数据自动读取路径；发布页改为审核与交接页，账号页仅管理账号标识。

只隐藏按钮或在提示词里说“不要发布”不足以实现这个要求。路由注册、后台任务、Skill 清单、共享脚本调用和 各执行器可见工具范围都要检查；不得保留能从其他入口继续执行发布的路径。开发验收使用替身/拦截器确认这些调用被拒绝，不通过真实平台发布来测试禁用效果。

各 Agent 的文件和终端工具也不能直写已批准版本、人工观测表或正式经营记忆。工作台 API/数据存储与 Agent 执行区应有独立权限：Agent 仅获得选定输入、可写候选输出目录及限权接口，提交结果由服务校验后入库。不假设现有 --ignore-rules 参数提供操作系统级文件隔离；实际隔离方案须在 T-01/T-06 验证。

### 3.4 现有资产如何接入

profiles、outputs、日历/想法 JSON 和已有记忆按“导入旧资产”处理：先形成清单、内容哈希、来源路径与可恢复副本，再由导入服务生成新对象。原文件作为来源保留，首次导入不覆盖它们。

旧输出可以成为候选作品，不能直接标为已审核。旧指标和发布状态先进入待人工核对的导入预览，不能自动升级成“已确认的人工真实记录”。已有 memory.md 是有来源的历史材料，涉及 IP/风格及经营原则的变化仍需用户采用。

## 4. 开发顺序

1. **T-01：建立通用执行与隔离基准工程。** 固定基准提交，记录本地依赖与许可证文件；验证执行适配接口与各客户端能力，Hermes 依赖改为可选；整理核心安装路径；彻底删除 OpenClaw 依赖、安装/执行/兼容分支和旧目录引用；停用发布及数据自动读取入口；补工作区身份和受限执行边界。
2. **T-02～T-03：把输出变成正式作品。** 在已有 Web 内增加版本编辑、来源引用、渠道快照审核、手动交接与记录。
3. **T-04～T-05：接入真实材料并做有依据的选题。** 复用已有画像/热点入口，补来源快照、知识与可解释推荐。
4. **T-06：接入 Agent 创作和 AI 复盘。** 抽取统一执行接口，接入 Pi、OpenCode、Codex、Claude Code、Gemini、可选 Hermes 和模型 API；统一 Context Pack、阶段产物、预算、取消、重试及人工数据只读权限。每个适配器独立验收。
5. **T-07～T-08：外部 Agent 接入及完整验收。** 支持 Codex、Claude Code、Cursor 等作为工作台 API 客户端；此方向与工作台主动调度本地 Agent 分开验证。远程 Web 使用本机执行器时另验设备连接与离线恢复。

工作包和完整字段契约见 [技术方案](03-技术设计与开发路线.md)。两份补充材料只用于填补这个底座的具体缺口；doocs/md 等候选需要先证明能改善现有流程，再决定是否引入。

以下是已有验收项在这个底座上的具体执行条件，不另建一套产品验收编号。

| 对应验收 | 必须留下的实际证据 |
|---|---|
| AC-001、AC-030 | 工程提交、实际客户端版本；干净环境不安装 OpenClaw 即可启动、创作和复盘；检查依赖、锁文件、安装脚本、运行时枚举及技能索引无 OpenClaw 依赖/执行分支/旧路径别名；旧配置作为未知值拒绝，不下载、探测或回退 |
| AC-030、AC-033 | 每条交付 Agent/API 路径分别验证成功、空回复、认证失效、额度不足、失败、取消和超时；用户正在编辑时，返回结果仍为候选版本；不读取或上传登录令牌，无静默切换执行方或计费方式 |
| AC-039、AC-040、AC-055 | Web、API、后台和 Agent 的发布/自动记录入口均不可执行；人仍可审核并导出对应快照 |
| AC-004、AC-044、AC-047 | Agent 不能将自生成数据改成人工数据，不能直接写正式数据库/经营记忆；采纳和更正有独立人工动作 |
| AC-010、AC-034、AC-104 | 旧资料导入可追溯与去重，旧文件可恢复；旧输出不自动获得审核状态 |
| AC-046、AC-053、AC-054 | 所选 Agent/API 执行器完成人工记录的 AI 复盘；外部客户端逐项验证，不能以本地 stdio 成功替代远程 MCP 验证 |

最终以当前修改后工程的测试、浏览器操作和真实素材闭环判断是否完成；当前文档确定了开发方向，没有宣称应用已经改造完成。
