# Loretide 开发设计规范

状态：2026-09-13 用户确认的强制开发约束。适用于所有新增或修改的 Web 页面，包括业务页面、开发诊断、测试入口、空状态和错误状态。

## 完整继承 Multica

**不要手写任何新页面的控件和布局。完整复用 Multica 的组件与排版规范，完全继承其颜色、字号及其他设计 token。** 不建立 Loretide 独立设计系统，也不以“临时测试页”为理由绕过这一约束。

- 控件直接使用 `app/packages/ui/components/` 中已有的按钮、输入框、选择器、标签页、表格、提示、卡片、弹窗等组件；不能用原生元素加自定义样式重新实现同类控件。
- 页面从 `app/packages/views/` 中同类现有页面及共享布局组件组合而来，沿用其页面容器、标题、导航、分区、表单行、工具栏、间距和响应式行为。不能另写一套页面骨架，再通过颜色近似冒充复用。
- 字体继承应用现有字体加载、主题和用户偏好；不单独指定字体族、不引入新字体、不覆盖全局字体。字号、字重、行高按现有组件及排版规范继承，禁止依赖浏览器默认字号。
- 颜色使用语义 token，继承主题与交互状态；禁止硬编码色值、另建色板或局部覆盖 token。圆角、边框、阴影、密度、焦点和禁用状态同样沿用现有组件。
- 只添加业务数据、行为、文案和现有组件公开支持的配置。现有组件不能覆盖需求时，先记录具体缺口和最接近的上游组件，继续完成可复用部分；不得自行引入新控件、布局体系或外部设计系统。

## 源码依据

| 来源 | 用途 |
|---|---|
| `app/CLAUDE.md` 的 UI Rules 与共享样式规则 | 上游工程、包边界及 UI 约束 |
| `app/packages/ui/styles/tokens.css` | 颜色、字号角色、行高、表面、圆角等 token 的权威定义 |
| `app/packages/ui/components/ui/` | 复用现有原子控件和交互行为 |
| `app/packages/views/layout/` | 复用共享页面布局及标题等结构 |
| `app/packages/views/settings/components/settings-page.tsx` 及其子页面 | 设置与管理类页面的布局、密度、标题和表单参照 |

以上为源码路径；当前文档仓库不包含被忽略的独立 `app/` checkout。实现时在应用工程中核对真实导出与用法，不凭文档猜测组件接口。

字号角色使用上游 `text-caption`、`text-label`、`text-body`、`text-title` 等定义；具体数值随上游 token 统一调整，不在业务页面复制一份数值。仅引用 token 不等于完成组件和布局复用。

## 开发与验收

1. 修改前确定同类 Multica 原生页面，列明复用的布局、控件和排版来源。
2. 检查组件导入和实际使用，排除自行实现的同类控件、页面骨架、硬编码颜色或字号、局部字体覆盖。
3. 浏览器对照原生页面，使用相同主题、缩放和字体设置核对字体、字号、行高、标题层级、间距、控件密度与状态；检查窄窗口、长文本、空状态、错误状态和键盘焦点。
4. 运行相关类型检查、静态检查及必要的行为验证。编译通过不能替代视觉验收。
5. 在 `records/` 记录改动文件、复用来源、实际检查及未完成项；未对齐不能标记设计验收通过。

## SOP 可操作阶段的执行口径（2026-09-15，用户确认）

在 SOP 跑通之前（LT-009 起），**不在 UI/UX 美观上花任何时间**。所有界面整套继承上游 Multica 的设计系统与设计 token：`packages/ui` 组件、`--text-*` 字号、语义色 token、间距与圆角。允许的 UI 工作只有一种——把功能挂到既有组合上；不新增控件、不调样式、不引入第二套视觉语言。PR 正文的「UI 影响」只需列出复用了哪些既有组件。视觉打磨若有必要，SOP 端到端跑通后另立任务。上文各条规则在本阶段仍全部有效。app 侧对应文本在 `docs/development/design/README.md`「SOP phase rule」。
