# 诊断页手动验证 runbook

## 这份文件是什么

**一次跑完的操作脚本。** 它把三份手动清单的 **64 条**按「页面/标签页」重排，让你少来回切换，而不是按特性分三次跑。

| 来源 | 条数 | 编号前缀 |
|---|---:|---|
| `specs/002-diag-package-stream-recovery/manual-ui-todo.md` | 37 | `002-V05-xx` / `002-V08-xx` / `002-V11-xx` |
| `specs/006-diag-trace-waterfall-regression/manual-ui-todo.md` | 20 | `006-W-x` / `006-V-x` / `006-L-x` |
| `specs/008-diag-linkage-and-invariants/manual-ui-todo.md` | 7 | `008-J-x` / `008-O-x` |

> **那两份文件仍是各自特性的权威来源。** 本 runbook 只是它们的执行顺序，不替代它们：条目的措辞、对应的 FR/SC、以及「这一条为什么存在」，以原文件为准；两边不一致时**以原文件为准**，并以更新本 runbook 的方式消除不一致。原文件**不删不改**。

按 `.specify/memory/constitution.md` 原则 II，UI 验收**不写单测、不做自动点击**。本 runbook 的每一条都由人在真实浏览器里执行。

## 1. 前置条件

### 1.1 起一个本机实例

```powershell
./scripts/local-windows.ps1 start
./scripts/local-windows.ps1 status
```

启动的先决条件、端口、日志位置、失败时该看哪个文件，全部见 **[Native Windows development](native-windows.md)**——本节不重复它。只提两点与本 runbook 直接相关的：

- `start` 会在启动前逐项检查前置条件，失败时**打印该看的日志与下一步命令**。卡住时先读它的输出，不要直接重试。
- `§9` 的两条要用 `stop` / `start` 制造断线，所以这两个命令全程都要能用。

登录后打开 **Web `/{workspaceSlug}/diagnostics`**（例：`/loretide-dev-check/diagnostics`），需要 **workspace owner / admin** 身份。**桌面端未挂载诊断页**，本 runbook 不涉及桌面端。

浏览器**开发者工具的 Network 面板**要打开——`§5` 与 `§8` 的多条要看请求。

### 1.2 测试数据全部自造，不要找现成的

诊断页的「**运行模拟场景**」按钮就是造数工具。`§3` 会让你跑 6 次模拟，后面所有条目都用这 6 次运行，不需要任何预置数据。

**不要用开发库里已有的运行来跑本 runbook**：一是你不知道它们是什么形态，二是 `§9` 会让某张表不可写。

### 1.3 不得对开发数据跑清理类用例

`§9` 的两条（`002-V11-10`、`002-V11-11`）要人为让某张表不可写，属**破坏性操作**。

**只在一次性本机实例上执行，绝不对开发业务库运行**（`docs/development/ai-collaboration.md`：清理型测试不得连接开发业务库）。跑完这两条后，该实例的数据**不要再用于其他验证**——重新 `stop` / `start` 并重跑 `§3` 造一批干净数据。

### 1.4 记录方式

- 每条只有三种结果：**通过** / **未通过** / **未执行**。
- **未执行不填通过。** 数据形态不具备、环境不允许、时间不够——都记「未执行」并在备注写原因。
- 依赖特定数据形态的条目现在**都有造数场景**，见 `§3.1`。造出来了就跑，跑不出来记「未执行」并写下卡在哪一步——**不得记为通过**。
- 唯一仍标「**如无可跳过**」的是 `006-L-5`：它要的是「原故障运行已被保留期裁剪或跨工作区不可读」，那是保留期与授权的行为，不是模拟器能造的数据形态。造法见 `§3.1` 末尾。

### 3.1 诊断自验场景（造出「本来造不出」的数据形态）

故障场景下拉里除了 16 个业务故障，还有 **9 个 `shape_` 开头的诊断自验场景**。它们只在隔离实例（`APP_ENV=development` 且 `LORETIDE_DIAGNOSTICS_TEST=1`）里可选，生产路径拿不到。跑法与普通场景一样：选中，运行一次。

**顺序有讲究**：`shape_sink_failure` 放最后，`shape_deep` 放倒数第二。

| 步 | 场景 | 得到什么 | 解锁的条目 |
|---:|---|---|---|
| 1 | `shape_concurrent` | 两根**可见重叠**（重叠约 200ms，各占半根）的横条，互不为父子 | `006-W-3` |
| 2 | `shape_orphan` | 一个显示为顶层**并标注「父 span 不在本次运行内」**的 span。若只见顶层、没有标注，那是缺陷，记「未通过」 | `006-W-5` |
| 3 | `shape_single_span` | 单行瀑布，不空图、不异常宽 | `006-W-6` |
| 4 | `shape_not_run` | 运行列表的回归结果列显示「未运行」 | `006-V-1` |
| 5 | `shape_regression_failed` | 显示「未通过」 | `006-V-3` |
| 6 | `shape_undecidable` | 显示「无法判定」，且两个原始值同时可见 | `006-V-5` |
| 7 | `shape_no_module` | 关联信息里 `module` 显示「未记录」 | `006-L-4`（`module` 那一半） |
| 8 | `shape_deep` | 250 个 span：瀑布出现「另有 N 条」折叠提示，失败步骤及其各级父节点在折叠状态下仍可见；点开后层级完整 | `006-W-7`、`006-W-8`、`008-O-3` |
| 9 | `shape_sink_failure` | 概览的 `sink_errors` 与 `dropped` 都 > 0 | `002-V11-01`、`002-V11-02`、`002-V05-15` |

**第 8 步会明显变慢**，是正常的：一次运行写 250 条技术事件，每条一个事务。**不要刷新**——刷新会拿到一个写了一半的运行。

**第 9 步不需要重建实例。** 失败只作用于那一次运行的写入；紧接着跑一次 `normal`，两个计数就不再增长。这一点本身值得确认一下（对应 `SC-005`）。

#### 两条不靠模拟器

| 条目 | 怎么造 |
|---|---|
| `008-O-2`（追踪内事件都没有版本） | **不需要新场景**。点面板的「触发页面错误（测试）」：它写出的事件不带对象版本且自带全新追踪号，正是这条要的形态。跳进那条追踪即可 |
| `006-L-5`（原故障运行不可读） | 不是数据形态，是**保留期与授权**的行为。用 `LORETIDE_DIAG_RETENTION_DAYS=1` 让被引用的运行过期，或从另一个工作区去引用它。都做不到才记「未执行」 |

#### 两条已知界限

- **导出只带 100 条技术事件。** `shape_deep` 有 250 个 span，但诊断包的导出上限是 100 条，所以导出文件里看不到全部。这是既有行为，不是本次交付的缺陷，`002-V08-x` 的导出条目不受影响。
- **`002-V11-02` 的 `dropped` 来源。** 第 9 步走的是**写入失败**路径，不是条目原文括注的「缓冲区溢出」路径。指标数值是真的。想看满环路径：**连跑 4 次 `shape_deep`**（4 × 250 条，缓冲环容量 1000）。

### 3.2 另外四条：保留期路径、授权路径，与一条已被覆盖的

主任务 2026-09-15 的预检报告把 19 条记为「模拟器造不出」，其中 4 条不在 `§3.1` 的九个场景里。**它们都不是数据形态**，裁决如下。

| 条目 | 属于 | 怎么造 |
|---|---|---|
| `008-J-4`（追踪事件已过保留期） | **保留期路径** | 与 `006-L-5` 同一处理：`LORETIDE_DIAG_RETENTION_DAYS=1` 让被引用的追踪事件过期，再点「查看追踪」。跳转本身要成功，事件表为空列表并有空态提示 |
| `002-V05-14`（保留期外记录不可读） | **保留期路径** | 同上。让一批记录过期后，对照概览的 `retention_days` 与技术日志最早一条的时间 |
| `002-V08-11`（他人 workspace 的 `run_id`） | **授权路径** | 需要在 `handler-tests` 工作区有**成员身份**，从那里取一个 `run_id`，再回到当前工作区试预览与下载。**没有成员身份就记「未执行 · 缺少授权前置」**，不是数据问题 |
| `002-V11-08`（> 200 条实时事件） | **已被 `§3.1` 覆盖** | 打开实时流，跑一次 `shape_deep`：250 个事件一次写入，正好越过「仅显示最近 200 条」的界 |

前三条**不该由模拟器承担**，理由与 `006-L-5` 相同：让模拟器造一条「已过期的记录」或「他人工作区的运行」，等于让它写一条本不该存在的记录。第四条只是此前没人发现 `shape_deep` 顺带解决了它。
