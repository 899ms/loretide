# Web 优先开发测试说明与对话记录

日期：2026-09-12  
用户问题：“如何方便开发测试？Multica 是桌面端 + Web 端，每次测试需要调试两个端吗？”  
核验基准：research/multica，提交 3551e72e76d2c276e550b668303646d1280fb1e2。

## 结论与依据

不需要每次同时调试两个界面。当前项目 v0.4.0 首版交付 Web，可把浏览器作为内容功能的主要验收入口，本机 Agent 通过独立 daemon 调用；Electron 桌面窗口不是必需组件。

- [CLAUDE.md](../research/multica/CLAUDE.md:18)明确 apps/web 是 Next.js，apps/desktop 是 Electron，core/ui/views 为共享业务与界面包。
- [Makefile](../research/multica/Makefile:149)支持按组件启动：默认 api,web，可另选 daemon 或 desktop；后端数据库仍是前置依赖。
- [官方 daemon 文档](https://multica.ai/docs/daemon-runtimes)说明 Desktop 会自动启动 daemon，Web/headless 可通过 CLI 独立启动 daemon。两种启动方式不能理解为 Web 必须先打开桌面客户端。
- [apps/web/package.json](../research/multica/apps/web/package.json)的 dev 使用 Next.js 开发服务；[桌面 package.json](../research/multica/apps/desktop/package.json)单独提供开发、构建与打包脚本，不需要每次测试重新生成安装包。

## 推荐的日常开发模式

| 改动或验证 | 启动和检查 | 是否需要桌面窗口 |
|---|---|---|
| 页面、素材、编辑器、审核、人工记录 | Web + Go API + 独立开发数据库/附件目录；浏览器验证刷新与保存 | 不需要 |
| 状态机、权限、业务接口 | 相关 Go/TS 单元与合同检查，事务测试使用独立数据库 | 不需要 |
| Agent 页面状态、错误与重试 | 拟新增可控测试执行器/事件夹具，明确 demo；覆盖运行中、失败、取消、重复和迟到结果 | 不需要；此替身尚未开发 |
| 本机 Codex/Claude 等真实调用 | Web + API + 数据库 + 独立配置的本机 daemon + 选定客户端 | 不需要，但必须通过 daemon 和客户端的实机验收 |
| 共享 core/ui/views 改动 | 浏览器主流程、相关包测试；若维护桌面兼容，补桌面类型/构建检查并按受影响页面烟测 | 不必每次全量测试两个端 |
| Electron IPC、原生文件对话框、托盘、深链接、桌面登录或 daemon 生命周期 | Electron 开发模式与相关平台回归；打包/更新器变更才增加安装包验证 | 需要 |
| 首版发布前 | Web 内容闭环、各交付 Agent/API 路径、隔离、恢复与正式构建 | 当前 Web 交付无需声称桌面产品已验收；若新增桌面交付范围则另设出口 |

共享代码减少重复开发，不保证两端路由、认证、存储、剪贴板或原生 API 行为一致。新业务页放在 packages/views 并不自动在桌面导航中出现，桌面支持需要相应路由/平台接入。

## 开发便利措施（建议，尚未实现）

1. 在后续 app/ 实施工程建立统一的启动、状态和停止入口，支持 Web 模式和 Web+Agent 模式；停止默认保留数据库与附件。
2. 开发服务常驻。前端改动使用开发服务更新；Go API/daemon 改动只重建或重启受影响组件。上游 api-dev 是 go run，不能据此保证 Go 已有自动热重载。
3. 为开发实例单独配置数据库、端口、附件目录、daemon 配置与任务目录；不能连到已有日常使用实例进行测试。按实例身份确认进程后再停止，避免误停其他任务。
4. 可重复的 demo 素材覆盖知识引用、版本冲突、审核和人工观测；测试执行器仅辅助流程开发，不替代真实模型、认证和隔离验收。
5. 日常按改动运行相关包与后端检查；发布前执行完整交付范围验收。普通测试不得自动调用本机已登录 Agent；真实调用显式选择模型、样例和运行范围。

上游命令参考：make up C=api,web；真实 Agent 联调时 make up C=api,web,daemon；确需桌面调试时使用 desktop 组件或 pnpm dev:desktop。这些是研究源码的入口，不是本机已验证的即用命令。当前 Windows 尚未完成 make/Bash/数据库环境核验，Web dev 脚本也依赖 sh；不能默认 PowerShell 可直接完整运行。后续 T-01 应提供验证过的 Windows 启动方式。WSL 与 Windows 的 Agent 安装/登录环境分开，不能把 Windows 已登录视为 WSL 自动可用。
