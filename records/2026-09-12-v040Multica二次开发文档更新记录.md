## 对话与确认

用户先问 Multica 是否有插件，因为界面只看到 Skill。研究固定提交发现 plugins_v1 默认关闭，设置页仅在开关启用时显示 Plugins，插件源码与实际开放状态不能混称。随后用户问是否需要把全部功能作为插件添加，答复明确建议：复用 Multica 基础能力，直接新增内容业务模块，Skill 驱动研究/创作/复盘，插件仅作可选辅助。用户认可并要求同步文档。

本次按 documentation-and-adrs 技能记录决策，延续项目既有 D-01～D-09 编号，新增 D-10；没有建立另一套 ADR 编号。当前文档升级为 v0.4.0，以 Multica 的 Next.js/Go/PostgreSQL 作为实施蓝图，旧 Easel/Hermes 方案标为历史。

## 实际修改

- 替换当前工作流、PRD、技术设计、验收及隔离文档的旧底座说明；保留 55 项功能、10 项非功能需求的 ID 和分期。
- 明确原生内容页面和 Go 服务拥有 IP、素材、作品版本、审核、人工发布/观测、复盘和经营记忆；Multica 任务状态与作品状态分开。
- 明确 Skill 的方法/输出职责、运行版本快照和服务端校验；插件关闭不得影响核心流程，插件借用用户会话不能伪造人类确认。
- 技术方案替换 Python Worker、FastAPI/Vite 路径与旧工程命令，改为共享 core/ui/views、Go handler/service、sqlc 和上游 Task/Run/daemon 映射。
- 增加 D10-V01～D10-V06 专项检查，覆盖插件关闭、任务结果入库、Skill 快照、敏感动作来源、正式存储与应用事务。
- 保留上游认证链接/Windows 复制回退、默认权限、缺失 Gemini CLI/完整 API 执行器与许可证条件等差距，均未写成已解决。
