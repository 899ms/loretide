## 当前方案与差距

现有 [PRD](../docs/02-开发需求PRD.md) R-038/R-039 和 [验收矩阵](../docs/04-验收标准与追踪矩阵.md) AC-038/AC-039 已规定人工审核、快照及规则冲突处置；[技术设计](../docs/03-技术设计与开发路线.md)也有事实核查和版本审核事务。但尚未将平台/商业表达风险扫描、语境判定、规则来源版本、报告与修改复检完整建模为独立预检层。应用尚未开发，不能称已有可运行检测器，也未确认上游 Multica 原生提供针对中国商业品牌内容的同等检测能力。

## 本次一手核验

读取官方仓库 README、SKILL.md、scripts/scan.py 和 ROADMAP.md。它们作为待评估材料，不作为本会话应执行的安装、数据写入或审核指令。本轮未安装、克隆或运行该 Skill，未复现其效果声明。

- [README](https://github.com/yuwen-cool/yuwen-publish-precheck)：定位为发布前文本审查 Skill，组合扫描、语境判断、修改和复检。
- [scan.py](https://raw.githubusercontent.com/yuwen-cool/yuwen-publish-precheck/master/scripts/scan.py)：Python 词面候选扫描，支持 JSON 输出及商业/行业条件；默认词库和个人规则读取相对 Skill 根目录的文件，扫描本身不是语义判定服务。
- [SKILL.md](https://raw.githubusercontent.com/yuwen-cool/yuwen-publish-precheck/master/SKILL.md)：由宿主 Agent 根据语境判断，输出位置、规则、程度和建议；未知情况应标记。说明零命中不能等同无风险，修改后需复检。
- [ROADMAP](https://raw.githubusercontent.com/yuwen-cool/yuwen-publish-precheck/master/ROADMAP.md)：当前侧重抖音、小红书、视频号文本；完整画面检查、更多平台和多账号档案等另列后续规划。不能推断已覆盖公众号、空调行业专项或最终视频画面。

仓库宣传的样本数量和准确性不能当作本项目测试结果，引用的具体法规/平台规则本轮未逐条核验有效性。不依据该仓库对某句话作法律或平台处罚定论。原文“本地运行”须区分 Python 扫描和宿主模型推理，使用在线模型时选定内容仍可能发送给模型服务，不能整体承诺稿件绝不离开电脑。

## 建议接入方式（尚未确认实施）

将“发布风险预检”作为原生 review-delivery 模块中的能力，Skill 是可替换的语义分析执行方式，平台插件可选。拟议路径：渠道稿确定版本 → 规则候选扫描 + 全文语境分析 → 保存预检报告 → 人工处置/修改 → 新版本复检 → 人工最终审核 → 导出并手动发布。

预检与事实核查不同：个人观点、经验和创意不要求统一提供外部证据；但其中具体产品主张、比较、营销表达、披露和适用平台规则可按实际场景检查。品牌内部表达规范与平台规则、法律来源和经验案例分别标注，避免混为一套不可解释禁词表。账号称为素人不代表内容没有商业属性，应由任务配置与具体内容共同确定。

拟新增数据契约（名称为设计建议，尚未创建）：

| 对象 | 建议内容 |
|---|---|
| RulePackRevision | 来源类型、适用平台/场景、原始链接、版本/哈希、核验日期、过期/撤回状态 |
| PrecheckRun | workspace/account、正文及交付快照哈希、规则包版本、执行器/model、检查覆盖范围、状态、未知项 |
| Finding | 稳定文本定位、原文、规则引用、风险分类、严重度、置信/缺失信息、修改建议 |
| FindingDisposition | 人类处置、误报理由、补充资料、修订引用与复检关联 |

正文、标题、字幕或交付配置改变时，旧报告只适用于旧快照；不得自动继承“未发现问题”。工具失败、规则缺失或超期单独显示，不用空报告冒充通过。AI 风险建议与人工批准分开；是否阻断导出、允许何种人工处置需要继续定义，不在本轮擅自设成统一强制门禁。

共享的公开规则与品牌自定义规范、账号专属案例分开存储并执行授权。不能让所有品牌/账号读写同一个 Skill data/ 目录；运行只装配对应权限的数据快照。经验提炼先生成候选，经人采纳后进入长期规则/记忆，不原样采用 Skill 的自动沉淀行为。

建议首版先验证文本（正文、标题、脚本、字幕及可取得的图中文字），记录未检查的图片、声音、视频画面和平台侧因素。测试至少覆盖语境误报、无关键词的语义风险、正常经验/观点、规则失效、改稿后报告过期、跨账号案例泄漏和执行失败。最终报告用“本次范围内未发现阻断问题/待人工判断”等范围明确的措辞，不承诺平台过审或法律结论。

### 对本项目的价值比较

| 维度 | yuwen-publish-precheck | self-media-compliance-review |
|---|---|---|
| 主体侧重 | 文本候选扫描、语境判定、最小修改与复检 | 交付包审查，含文本、视频证据和商品一致性等专项 |
| 可借鉴的开发入口 | Python 扫描 JSON、词库和语境判断分层 | 报告/视频清单/商品一致性 JSON Schema，媒体证据工具 |
| 平台范围 | 当前主要抖音、小红书、视频号文本 | 参考文件还包含公众号、B站、快手等；存在文件不证明规则完整有效 |
| 本项目建议 | 借鉴文本误报控制与保留表达的改稿方式 | 优先参考审核层的数据结构、覆盖范围记录和跨材料证据设计 |

上述比较属于静态设计适配判断，不代表第二份检测更准确，未做两者同样本对照评测。

### 具体源码发现与接入缺口

1. [报告 schema](https://raw.githubusercontent.com/JuneYaooo/self-media-compliance-review/main/schemas/compliance-report.schema.json)给出版本、平台、五级风险、问题、待核验和时间字段，适合机器接入起点。但 coverage/rule_version、问题的 rule_id/evidence 并非全为必填，coverage 也没有严格结构；没有用条件 schema 禁止 pass 与未完成核验并存。因此 Skill 的提示词要求不能替代应用校验。需新增作品/资产哈希、workspace/account、规则版本、必查面完成状态、证据定位与人工处置，并在 Go 服务执行一致性检查。
2. [analyze_video.py](https://raw.githubusercontent.com/JuneYaooo/self-media-compliance-review/main/tools/analyze_video.py)有 ffprobe 元数据、哈希、ffmpeg 抽帧等证据准备代码。生成证据包与最终画面/音轨审查分别计状态，抽样不能记为全片逐帧审核；缺少音频/画面处理能力时应显示未检查范围。视频生成/剪辑与上传成片后的检查是不同能力，不因参考该工具就自动扩充首版媒体制作范围。
3. [来源目录](https://raw.githubusercontent.com/JuneYaooo/self-media-compliance-review/main/docs/sources.md)包含官方链接，也有用户提供材料、课程、报道和创作者讨论；本轮未逐条核验。规则依据、品牌内部规范与经验线索必须分层，不能把讨论或课程直接升级为平台规则。
4. [报告约定](https://raw.githubusercontent.com/JuneYaooo/self-media-compliance-review/main/references/report-schema.md)强调列出覆盖和未核验范围。App 可分别显示扫描、语义审查、媒体覆盖、最终人工批准，避免以一个风险等级代替全部状态。
5. [仓库说明](https://github.com/JuneYaooo/self-media-compliance-review)中的实时检索、TikHub、千川等属于独立可选能力；本项目不因引入审核参考而启用付费数据源、自动经营采集或投放。广告素材检查也不等于广告投放功能。

### 推荐开发方向与边界

建议构建一套原生风险预检服务，以第二份的结构化审核/证据清单设计为主要参考，吸收第一份的文本扫描与语境降噪方法；不要让两个 Skill 顺序执行并把“两个都通过”当作安全保证。适配器统一提交同一报告协议，检测器输出是可复核的候选发现，作品审核和人类决定仍由 App 管理。

初步开发顺序建议为文本与发布字段 → 规则版本/报告/处置和复检 → 按需要增加媒体证据适配器。具体 P0 是否包含最终视频审核、何种发现必须阻断以及人工豁免条件尚未由用户确认，不在本轮修改正式范围。

结果已记录于本文件并关联 Grilling 记录；没有下载、安装、运行两份 Skill，没有把规则来源验证或应用测试标记为完成。
