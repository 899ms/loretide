# 工作空间隔离核对记录

日期：2026-09-12  
用户问题：有工作空间隔离的设定吗？  
核对对象：当前 v0.2.2 工作流需求、技术方案、验收标准与底座改造映射。

## 结论

有隔离设计，但目前属于文档要求，尚未实现或通过运行验证。业务数据与权限隔离已较具体；本地 Agent 的操作系统级隔离机制还未选定并验证。

| 层面 | 已写入的要求 | 主要依据 |
|---|---|---|
| 业务数据 | 所有业务对象带 workspace_id；服务端从认证身份确定可访问工作区，不能信任请求传入的 ID；跨工作区查询、附件、引用和搜索必须拒绝。 | 技术方案 §3 中的公共字段及数据约束；PRD R-001；AC-001、AC-103、AC-106 |
| API 与操作权限 | 工作流 Key 限定工作区、项目和 scope，可吊销；Agent 不能人审批准或写人工真实记录。 | PRD R-055、NFR-03；技术方案 §7；AC-055、AC-103 |
| 任务与会话 | 按工作区、run_id、step_id 和基础版本绑定会话，不复用全局最近会话；每次只读取选定上下文。 | 技术方案 §5 |
| Agent 执行区域 | 限制可执行文件、参数、工作目录和工具；只提供授权输入、候选输出目录及限权接口，与正式业务存储分离，禁止越权直写。 | 技术方案 §5；底座改造映射 §3.3 |

首版界面仍是一个个人工作区、一个主要 IP；数据模型保留工作区隔离能力，不等于已经包含多个工作区切换、多个 IP 或完整团队管理。

## 尚需落实

文档没有确定各客户端在 Windows 上的具体进程/文件沙箱实现，也没有验证只读输入、目录外访问、符号链接逃逸、继承权限、子进程权限和跨任务会话隔离。应在 T-01/T-06 实现并证明实际边界，同时验证官方客户端正常认证与执行。

将不同任务放进不同目录、设置 cwd 或在提示词里要求不越界，均不能单独证明具有文件或进程隔离。官方客户端自行管理登录也不自动提供工作区隔离。本轮未新增容器、虚拟机或独立系统账号等选型要求。
