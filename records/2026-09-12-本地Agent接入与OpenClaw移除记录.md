# 本地 Agent 接入与 OpenClaw 移除记录

日期：2026-09-12  
状态：架构决定已确认，核心文档更新为 v0.2.2；应用代码尚未拉取、修改或运行。

## 用户要求与决定

用户询问能否像 Orca / Multica 一样，通过本机已经登录的 Codex、Claude Code、Gemini 执行 AI 任务，并进一步确认是否采用同类安全调用方案。随后明确：“不需要接受 openclaw，可以完全抛弃 openclaw 依赖”。截图指向旧改造表中仍允许 OpenClaw 兼容分支及迁移期旧路径的表述；这些保留条款被本次决定取代。

1. 继续以 Easel-For-Hermes 为派生代码基准，沿用 React/TypeScript/Vite 与 Python/FastAPI。Hermes 保留为默认执行路径。
2. 增加本地任务执行适配层，可选择官方 Codex、Claude Code、Gemini 客户端。由客户端自己完成登录认证、缓存与刷新；工作台提交受限上下文、接收候选成果，不提取或转交订阅令牌给 Hermes。
3. 彻底移除 OpenClaw 运行依赖、安装/探测/执行/兼容分支及旧目录引用，不保留旧路径别名、软链接或回退。未知运行时配置直接报错。可复用的内容技能迁入项目自有中性目录，删除旧入口；许可证与上游历史证据保留。
4. 工作台本地部署时由本机 Worker 启动客户端；远程 Web 部署时需要本机执行器与工作台配对，领取任务并交回结果。用户电脑离线时任务等待或报告中断，不能由服务器擅自接管登录或改用收费 API。
5. 中国社交媒体、个人优先、人工审核、手动发布与真实记录、AI 复盘等业务范围继续有效。所有执行方只能提交候选成果，不能代替人写真实指标、审核通过或采纳长期记忆。

## 为什么这样选择

用户希望使用现有本地 Agent 及其官方认证能力，同时完全去除 OpenClaw 的维护负担。任务执行适配层可保留当前 Web 技术栈，并把执行客户端和模型提供方分开记录。它不是供 Hermes 任意推理调用的通用订阅 API 网关，也不要求每次先由 Hermes 再套一层 Agent。

此处确认的是官方客户端进程调用模式，不是对 Orca / Multica 全部源码的安全审计结论。隔离、客户端兼容性和真实模型调用仍须逐项实现与验证。本机启动客户端通常仍会把所选任务材料发送到厂商在线模型服务。

本机仅做了 PATH 检测：codex、claude、gemini 分别解析到当前用户 AppData/Roaming/npm 下的同名 .ps1 入口；hermes 未在当前 PATH 找到，不等于所有位置均未安装。没有读取认证文件、获取登录令牌、调用模型、刷新登录、安装运行时或使用重置额度。

## 实现后的验收要求

- 检查派生工程的依赖与锁文件、安装/doctor 脚本、运行时选择、规则加载和技能索引；OpenClaw 无依赖、执行入口或兼容别名。历史来源、许可证和拒绝未知配置的测试文字不算运行依赖。
- 干净 Windows 环境不安装 OpenClaw 即可启动；Hermes 和每个已启用官方客户端分别完成真实创作及人工记录的 AI 复盘。
- 使用测试凭据和受限目录验证认证不被提取/转交/上传、越权写入被拒绝；认证过期、额度不足、超时、取消及机器离线如实展示。取消效果按实际客户端能力报告，不能只把 UI 改成已取消。
- 输出经过服务端校验，以运行、阶段、作品和基础版本绑定；不覆盖用户编辑、人工观测、审核通过或已采纳记忆。

本轮只验证文档一致性、链接、围栏与需求/验收编号；这些检查不代表应用或安全验收通过。
