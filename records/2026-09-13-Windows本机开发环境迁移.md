# Windows 本机开发环境迁移

## 范围与决定

将当前开发入口迁回 Windows 原生环境，不使用 Docker，不恢复已暂停的 Sol 任务。保留远端环境、数据库及本地未提交改动。此次不等于诊断业务全部验收，也不启用真实 AI 执行器。

## 已执行与证据

- 将远端源文件快照导入独立 app checkout；被替换本地文件先保存至 `app/data/local-migration/local-before/`，差异清单位于同目录 `changes.json`。
- 远端 PostgreSQL 使用 custom dump 备份，恢复到本机 `loretide_dev`；初始核对 2 个 workspace、3 条 content_diagnostic_run。远端上传目录检查为 0 个文件。
- Node 24.14.0、仓库 pnpm 10.28.2；Go 自动工具链完成 API build。PostgreSQL 17.11 使用 `F:\loretide-runtime` ASCII 路径，避开中文二进制路径导致的 initdb 编码错误。
- 本机 API `/health` 正常。浏览器通过本地开发账号验证码登录，原验收任务可见；诊断页八个 tab 可见，API/database/web 显示 healthy，构建标识 `windows-local-migration`。daemon/executor/files/search 保持未验证。
- 本机 API 所属进程异常退出演练：PID 13556 → 36880，约 4.1 秒自动恢复。
- 本机 Web 所属进程树异常退出演练：PID 15540 → 30560，诊断 URL 约 39.3 秒恢复 HTTP 200（包含开发编译）。
- Go diagnostics 包测试通过（未设置独立集成数据库，不作为 DB 集成通过）；Core typecheck 通过；模块边界检查 3519 files / 12 modules 通过。

| 文件 | 用途 |
|---|---|
| `app/scripts/local-windows.ps1` | start/stop/status/build 入口 |
