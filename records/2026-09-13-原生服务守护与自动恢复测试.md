# 原生服务守护与自动恢复测试

用户要求补齐服务守护和自动恢复，不重启机器。目标为 box@100.109.104.61 的 /home/box/loretide-dev。

## 已部署

远端 PID 1 为 tini，systemd 用户实例 offline。安装 Debian Supervisor 4.2.5，用独立配置以 box 身份管理 PostgreSQL、API、Web。控制 socket 位于 data/native，权限 0600，不开放管理 HTTP 端口。日志 10 MB 轮转，保留 3 份。没有安装 Docker 或修改 Bot 原有进程。

先核验旧 API 二进制、Web cwd 和父子进程关系，精确停止原手动进程，数据库正常停止后由 Supervisor 接管。未向旧进程共享的进程组发送信号。新服务各自拥有独立进程组。

服务异常退出自动重启；启动失败最多重试 10 次后 FATAL，避免无限启动循环。明确的 supervisorctl stop 保持 STOPPED。进程存活但失去响应的 watchdog、Supervisor 自身退出后的拉起和平台开机入口不在此次实现范围内。

## 实测结果

对每个服务独立进程组发送 SIGKILL，检查新 PID、RUNNING 和 HTTP；这是实际故障注入，不是模拟状态。

| 服务 | 原 PID → 新 PID | RUNNING | HTTP 恢复 |
| --- | --- | --- | --- |
| PostgreSQL | 64346 → 65080 | 3.80 秒 | API health 200，3.81 秒 |
| API | 64347 → 65119 | 6.40 秒 | health 200，6.40 秒 |
| Web | 64348 → 65184 | 6.33 秒 | /login 200，52.70 秒，包含开发重新编译 |

数据库查询确认原验收任务保留；浏览器刷新后保持登录、工作区和 LORE-1。当前 cgroup OOM/OOM kill 均 0。另执行 API stop，等待 3 秒仍 STOPPED，随后 start 成功且 health 200。所有测试结束时三服务均恢复运行。

这证明服务进程异常退出可恢复，不等于所有故障都能自愈，也不证明平台重建后的持久性；没有重启或重建 VPS。
