# 开发冷编译峰值与耗时

## 本轮请求与测量范围

用户要求测一次完整冷编译的峰值和耗时。测量对象为当前 Multica/Loretide Web 开发模式的工作区路由 `/loretide-dev-check/issues`，等待HTTP响应体完整读取，不是全项目生产build、全部路由编译或依赖安装测试。

停止Web，保留并移走整个 apps/web/.next，重新创建Web容器清零cgroup峰值；依赖包和宿主机文件页缓存未清除。旧目录保留在服务器 `/home/opsadmin/loretide-dev/apps/web/.next.before-cold-20260913-042829`。已有浏览器可能在重启后自动重连，属于本次测量环境；不是完全无其他客户端的基准测试。

## 配置

- VPS：4核、约7.6GiB物理内存；Web限制2核、5GiB，Node堆3072MiB。
- 其他11个用户容器保持停止；Loretide API与数据库运行。
- Webpack开发模式启用内存优化、禁用开发编译缓存，保留source map。
- 每约2秒读取cgroup memory.current、memory.peak与memory.events；峰值来自内核计数，包含容器全部进程及计入cgroup的文件缓存，不等于单个V8堆，也不是整台VPS峰值。

## 结果

| 指标 | 实测 |
| --- | --- |
| 服务Ready（从重新创建开始） | 10.90秒 |
| 无缓存页面首次请求至完整响应 | 159.00秒，约2分39秒 |
| 从创建容器到结束采样 | 171.61秒，约2分52秒，含轮询开销 |
| 容器内存峰值 | 4,845,318,144字节，约4.513GiB，占5GiB上限90.25% |
| 首次HTTP结果 | 200，完整响应315258字节 |
| 内存事件 | oom=0、oom_kill=0、max=0；未触及容器硬限制 |
| 同一路由热访问 | 200，0.309秒（服务器回环请求） |
| 测试后宿主可用内存 | 2882MiB；不是全过程最低值 |

本轮为单次测量，不是P95或多次平均值；HTTP响应完成不等同浏览器交互就绪时间。此前已单独验证工作区渲染和刷新，本轮未新增浏览器交互时延指标。

## 判断与后续

当前配置能完成一次工作区冷编译，但5GiB容器仅约0.49GiB峰值余量，首编耗时明显。现有8GB服务器适合当前停止其他服务后的单路开发，不能据此承诺多套并行构建或恢复所有服务后仍稳定。热访问明显快于冷编译；此数据不能推断生产运行需要相同内存。

原编译缓存保留不删除，其他容器不自动恢复，开发服务继续运行。脚本与配置保存在独立应用Git；文档和原始指标同步文档GitHub仓库。
