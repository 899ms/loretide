# 本机独立数据库回归与并发审查

## 执行范围

在现有 Windows 原生环境中建立独立测试库，核验诊断与 handler，审查暂停任务遗留的 workspace 删除并发方案；未唤醒 Sol，未调用真实 AI 执行器，未修改远端服务。

## 已验证结果

- 新建独立数据库及同名 NOSUPERUSER/NOCREATEDB/NOCREATEROLE 角色，私有配置仅保存在 app/data/windows/test-db.json。迁移命令 `go run ./cmd/migrate up` 成功。未复制开发业务数据到测试库。
- 设置真实独立数据库连接后，`go test ./internal/content/diagnostics -count=1 -json`：25 个测试/子测试通过，无跳过。
- 首次完整 handler 回归只发现两处 Windows 兼容失败：daemon 路径期望硬编码 `/`；技能路径校验错误接受 Unix 风格绝对路径。
- 新增 portable path 用例，修复前稳定复现 5 类错误接受：Unix 绝对路径、Windows 根相对路径、驱动器相对路径、冒号流路径和 NUL。
- 修复后 `go test ./internal/handler -count=1 -json`：3697 个测试/子测试通过，47 跳过，0 失败，40.373 秒。计数包含子测试，不是 3697 个独立顶层场景。跳过主要涉及 Redis、外部服务等，不计作通过。
- Vitest：core 实时流用例、Web 下载用例分别通过；模块边界检查 3520 files / 12 modules 通过。
- 浏览器只读核对本机诊断概览：API/Web/database healthy，八个面板可见，真实执行器仍禁用。本轮没有重新声称完成下载落盘或断线恢复的全部浏览器矩阵。

## 并发方案审查

诊断 Store 的 run/audit/technical 写入通过公开 WorkspaceWriteGuard 在同一事务内先取得 workspace 的 FOR KEY SHARE，再写记录并提交；DeleteWorkspace 先取得 FOR UPDATE，再清理三个诊断表。写入先发生则删除等待后清理；删除先提交则后续写入拒绝。未把 workspace 私有 SQL 放进诊断模块。

现有并发测试覆盖两个方向、审计原子性、technical 拒绝后计数和内存缓存，以及相邻 workspace 数据保留，本轮真实数据库执行通过。本结论限于该协议，不代表所有业务模块或真实执行器安全验收完成。
