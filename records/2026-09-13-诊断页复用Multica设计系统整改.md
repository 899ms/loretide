# 诊断页复用 Multica 设计系统整改

## 请求与范围

用户要求整改开发诊断页，禁止自行手写控件和页面布局，完整继承 Multica 组件、排版和设计 token。本次只整改诊断页呈现与必要的共享组件导出，不将 UI 整改等同执行器安全或完整诊断前置全部验收。

## 文件关联与用途

| 应用工程文件（相对 app/） | 用途 |
|---|---|
| `packages/views/content/diagnostics/index.tsx` | 八个诊断面板改用 SettingsContent、SettingsTab、SettingsSection、SettingsCard、SettingsRow；按钮、输入、选择器、标签页、表格、状态标签、提示及耗时条均复用 UI 包组件；错误恢复页也沿用共享布局 |
| `packages/views/settings/components/settings-layout.tsx` | 从原生设置页提取现有内容容器为 SettingsContent，保持原有宽度、边距、滚动及响应式规则 |
| `packages/views/settings/components/settings-page.tsx` | 原生设置页同样调用 SettingsContent，避免复制后独立演化 |
| `packages/views/settings/index.ts` | 导出共享内容容器 |
| `packages/views/package.json` | 提供 settings/layout 与 layout/page-header 精确导出，诊断页只导入需要的共享布局 |
| `scripts/content-boundaries.json` | 允许内容模块使用上述两个共享布局入口，其余模块边界继续检查 |

没有修改上游颜色、字体、字号 token 或引入第二套设计系统。窄屏导航直接复用 PageHeader 及其原生侧栏触发器。原先自行实现的耗时条换成 Progress / ProgressLabel / ProgressValue。
