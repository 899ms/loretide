# Contract: 请求头与路径/URL 脱敏

供**全部 sink 与导出复用的同一套规则**，无绕过路径（spec FR-007）。

## 请求身份 = 路由模板 + HTTP 方法 + 响应状态码

由两个字段承载：`Event.route` = `<METHOD> <路由模板>`（例如 `GET /api/content-diagnostics/events`），`Event.status` = 响应状态码（例如 `200`）。

| 记什么 | 不记什么 |
|---|---|
| 路由模板（注册时的模式，含 `{id}` 占位符） | **原始路径**——不回退、不清洗后使用 |
| HTTP 方法 | **查询串取值** |
| 响应状态码 | **查询串键名** |
| | **完整路径的哈希**（任何不可逆或可关联的摘要） |

- 路由模板取自注册时的模式，是编译期即确定的有限集合，**不含任何用户输入**，因此不需要正则清洗，也就不存在「清洗漏一种 id 写法」的风险。
- 取不到路由模板时（未匹配任何路由）`route` 写 `""`，**不**回退到实际路径。

## 请求头准入（三档，逐名列举）

名称比对**大小写不敏感**（按 `textproto.CanonicalMIMEHeaderKey` 归一）。**未列入者默认不记。**

### 第一档 · 记录值

| 头 |
|---|
| `traceparent` |
| `tracestate` |
| `x-diagnostic-trace` |
| `x-request-id` |
| `x-workspace-id` |
| `content-type` |
| `content-length` |

### 第二档 · 只记录「存在」，不记录值

| 头 |
|---|
| `user-agent` |
| `accept` |

由 `Event.headers_present` 承载：一个**只含名称**的列表，取值恒为本档名单的子集。**不得**记录取值、长度、前缀或任何摘要——长度本身也是取值的一种泄漏。因为列表内容只能取自一个编译期固定的名单，它不可能携带用户输入。

### 第三档 · 一律不记（名称、取值、片段、长度都不出现）

| 头 | 形式 |
|---|---|
| `authorization` | 逐名 |
| `cookie` | 逐名 |
| `set-cookie` | 逐名 |
| `x-api-key` | 逐名 |
| `proxy-authorization` | 逐名 |
| `*-token` | 名称模式 |
| `*-secret` | 名称模式 |
| `*-key` | 名称模式 |
| `*-password` | 名称模式 |

名称模式为后缀匹配，同样大小写不敏感。四条模式与逐名项是**冗余**关系而非替代：`x-api-key` 已被 `*-key` 覆盖，仍单列，以便名单被误改时仍有一层拦截。

### 通用

- 同名多值：不拼接，整体按未列入处理。
- 第三档优先于第一、二档：一个头若同时匹配模式与某一档白名单，按第三档处理。

## 入站 trace 的关联属性（`Event.upstream_trace`）

- 只有校验通过且未被采信为父级时写入；被采信时不写。
- 值为固定形状的 W3C trace-id，不承载自由文本。

## 通用规则

| 规则 | 说明 |
|---|---|
| 整体丢弃优于部分保留 | 不输出截断前缀、长度、哈希等可还原或可关联的片段 |
| 与既有字段级白名单同口径 | `oneOf()` / `token` / `hexID` 的行为不变，本功能只增加两条具名规则 |
| 导出复用 | 预览与下载两条路径得到同一套脱敏结果，`redacted` 为真 |

## 负例（必须有测试）

| 输入 | 期望 |
|---|---|
| `Authorization: Bearer <token>` | 事件与导出包中不出现该头的名称或取值 |
| `authorization`（小写） | 同上——大小写不影响判定 |
| 路径 `/api/x/9f2c…/detail` | 记 `GET /api/x/{id}/detail`，不出现该 id |
| 查询串 `?token=abc&q=secret` | 不出现 `token`、`abc`、`q`、`secret` |
| 路径里塞令牌 | 按未准入处理，不因为「它在路径里」就当安全 |
| 同名多值请求头 | 整体不记，不因拼接泄漏未准入部分 |
| 超长 URL / 超多请求头 | 有界；超出部分整体丢弃而非截断保留 |
