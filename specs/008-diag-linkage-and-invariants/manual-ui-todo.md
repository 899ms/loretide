# 手动验收清单：008 诊断关联跳转与不变量断言

按 constitution 原则 II，界面行为**不写自动测试、不用浏览器自动点击**，只能由用户在真实浏览器中确认。

**全部条目状态：待用户验证。** 未执行的条目一律记为未执行，不得因为「代码写了」或「PR 合了」标为通过。

前置：`make up` 起本地环境，以 owner/admin 身份进入 `/{workspace}/diagnostics`，先跑一次模拟（「固定故障复现」→ 任一故障场景）以产生数据。

## J — 审计事件到技术追踪的跳转（G1）

| # | 步骤 | 预期 | 状态 |
|---|---|---|---|
| J-1 | 在操作时间线上找一条**带追踪编号**的事件，点「查看追踪」 | 切到**单次追踪**页；该页**同屏**显示瀑布、「对象与版本」卡片与事件表，只含该次追踪；组件 / 严重级 / 错误码 / 时间范围筛选**均已清空**；分页回到第一页。**不需要刷新页面，也不需要手输追踪编号** | 待用户验证 |
| J-2 | 先设好严重级与时间范围筛选，再点另一条事件的「查看追踪」 | 上一次的筛选**不残留**，结果只由本次事件决定 | 待用户验证 |
| J-3 | 找一条**没有追踪编号**的事件 | 「查看追踪」呈**不可用**状态并给出说明；点击**不切页**、**不**显示一屏无关日志 | 待用户验证 |
| J-4 | 对一条追踪编号存在但该追踪事件已过保留期的事件点「查看追踪」 | 切到**单次追踪**页成功，事件表为**空列表**并有空态提示——与 J-3 的「不可跳转」在观感上可区分 | 待用户验证 |

> **2026-09-15 实施期修正，原措辞与实现不符**：J-1 / J-4 原写「切到**技术日志**页」，实际落点是**单次追踪**页（`onTrace` 执行 `setTab(3)`）。主任务 2026-09-15 裁决**改规格不改落点**——单次追踪本就是正确目标，对象与版本卡片与事件表都在该分支下。
>
> 同时修掉一个由此暴露的真 bug：该页的渲染条件曾是 `tab === 3 && !runId && trace`，而 `onTrace` **必然**设置 `runId`，于是走 J-1 这条路进来时 **O-1 / O-2 / O-3 的「对象与版本」卡片永远不显示**——此前只能靠刷新页面手输追踪编号才看得到。**这三条在本次修复前实际不可验收。**（`specs/011-diag-panel-time-and-jump`）

**J-3 是本特性修掉的缺陷**：改动前点它会静默跳到未筛选的技术日志，读者会把无关日志当成本次故障的原因。验收时请重点确认这一条。

## O — 对象与版本的呈现（G2）

交付位置：**「单次追踪」页**（从操作时间线点「查看追踪」进入后）事件表上方的「对象与版本」卡片。

| # | 步骤 | 预期 | 状态 |
|---|---|---|---|
| O-1 | 跳进一条**带对象版本**的追踪 | 卡片显示对象类型与标识，并按**先后顺序**列出本页出现过的版本，每个版本带出现次数，不重复 | 待用户验证 |
| O-2 | 跳进一条事件**都没有记录版本**的追踪 | 显示「未记录版本」，**不显示空白**、**不伪造**版本号 | 待用户验证 |
| O-3 | 让某个对象的事件**跨多页**（调小分页或多跑几次模拟），在其中一页查看该对象 | 只显示**当前页内**出现过的版本，且卡片下方有范围说明（「仅统计本页出现过的版本」）。**确认这句说明确实能让读者看懂这不是该对象的全部版本** | 待用户验证 |

**O-3 是 Q2 裁决 A 的已知代价**（不新增数据读取路径 → 只能在已取回的事件内归拢），不是缺陷。它进手动清单的目的是确认这个限制**对读者可见**，而不是被界面悄悄吞掉。
