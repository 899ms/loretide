## 迁移约束检查的判定

**范围**：`server/migrations/` 中编号 **≥ 468** 且文件名含 `content_` 的全部 `.up.sql` 与 `.down.sql`。

| 规则 | 判定 | 失败信息 |
|---|---|---|
| **R1 无外键** | 剥掉注释与字符串后，不得出现 `REFERENCES` / `FOREIGN KEY` | 点名文件与命中的关键字 |
| **R2 无级联** | 同上，不得出现 `CASCADE` | 同上 |
| **R3 索引并发** | 每一条 `CREATE INDEX` / `CREATE UNIQUE INDEX` MUST 带 `CONCURRENTLY` | 点名文件与该条语句 |
| **R4 并发索引单语句** | 含并发索引的文件，其语句数 MUST 为 1 | 点名文件与实际语句数 |

**为什么要剥注释**：一条写着 `-- 这里刻意不加 FOREIGN KEY` 的注释，恰恰在说约束被遵守了；字面匹配会把它判成违规。

**为什么设下界 468**：`468` 是 diagnostics 模块第一个迁移。不设下界会把全仓 1000+ 个历史迁移扫进来，别的模块的 FK 会立刻变成本模块的红线。

## 静态检查的判定

**扫描清单（显式，不通配）**：

| 文件 | 在链路里的角色 |
|---|---|
| `apps/web/platform/content-diagnostics.ts` | 保存到本机（`createObjectURL` + `<a>` + `click`） |
| `packages/views/content/diagnostics/index.tsx` | 面板，`download` 由 props 注入 |
| `packages/core/content/diagnostics/queries.ts` | `download` mutation，调用 `api.contentDiagnosticDownload` |
| `apps/web/app/[workspaceSlug]/(dashboard)/diagnostics/page.tsx` | 把前两者接起来 |

**显式排除**：`packages/core/api/client.ts`。下载经 `api.contentDiagnosticDownload` → `fetchRaw` 走共享客户端，是**合法的同源 API 调用**；判红等于把正常下载判成违规。

| 规则 | 判定 |
|---|---|
| **P1 无原生网络原语** | 清单内文件不得出现 `fetch` / `XMLHttpRequest` / `sendBeacon` / `new WebSocket` |
| **P2 词边界** | 匹配 MUST 按词边界。`fetch(` 的朴素子串匹配会命中 React Query 的 `refetch()`——**已实测 `index.tsx` 有 4 处**，朴素匹配 4 个误报，词边界 0 个 |
| **P3 清单有效** | 清单内每个文件 MUST 存在；任一缺失即失败。扫不到文件的检查会永远绿 |

**输出契约**：通过退出 0 并给一行摘要；违规退出非 0，每条违规一行，**点名文件与命中的原语**。
