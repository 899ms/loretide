# Contract: 计划轮换

## 服务端 `ContentDiagnosticStream`

| 规则 | 内容 |
|---|---|
| S-1 | 计划窗口的最后一页 `rotate` 为真，且**在窗口边界之前**写出并冲刷 |
| S-2 | 轮换判定在**写这一页之前**完成，判据是「再等一个 ticker 周期会越过窗口边界」 |
| S-3 | 一条流中 `rotate` 为真的页**有且仅有一页**，且是最后一页 |
| S-4 | 窗口到期之后**零动作**：不再有数据库查询、不再有响应写出 |
| S-5 | 成员身份撤销、客户端断开、查询失败导致的结束**不带 rotate** |
| S-6 | 窗口短于一个 ticker 周期时，**首页即轮换页**，流立刻结束——一页是对的 |

**不变的**：端点、查询参数、`Page` 的字段集、`Content-Type`、既有的每跳成员身份复核。

## 客户端 `stream-state.ts`

**不改**。今天已经正确：`page` 事件在 `rotate` 为真时保持 `connected` 并返回 `reconnectInMs: 0`，`connect` 在 `status === "connected"` 时是 no-op。本特性只为它补一条基于真实报文的断言。

## 夹具 `rotation-last-page.json`

两侧唯一的共同真相来源。

| 侧 | 断言 |
|---|---|
| Go | 跑完一个真实窗口，最后一页的**原始 JSON 字节**与夹具逐字节相等 |
| TS | 读同一夹具 → `pageSchema` 解析 → `nextStreamState` → `status !== "disconnected"` 且 `reconnectInMs === 0` |

夹具过期时 Go 那侧先红。**MUST NOT** 让两侧各自手搓对象——那正是让 50ms 测试骗过所有人的同一类错误。

## 最容易悄悄失败的地方

- **只断言「末页 rotate 为真」而不断言「结束早于窗口边界」**：改动前的代码也能让末页 rotate 为真（实测九次全中），缺陷恰恰在于它**晚了 11ms**。不测时刻，就等于没测这次修复。
- **继续用短于一个 ticker 周期的窗口**：那条路径生产环境走不到，绿色没有意义。
- **为了让流安静结束而给所有结束加 rotate**：真断线会被藏起来，用户看不到本该看到的提示。
