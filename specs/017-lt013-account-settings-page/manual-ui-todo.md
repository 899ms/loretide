# 手动验证清单：账号设置页面（LT-013）

按 `.specify/memory/constitution.md` **原则 II**，UI 验收不写单测、不做自动点击。以下每条都由人在**真实浏览器**里执行。

**默认全部未勾。** 原则 X：勾了不等于验过——只有真跑过的人才能勾。

## 前置

1. 起一个本机实例（见 `docs/development/native-windows.md` 或 `native-linux.md`）。
2. 以 **workspace owner / admin** 登录，进入某个品牌空间。
3. 打开 **`/{workspaceSlug}/accounts`**。本 PR **不加侧栏入口**（见 `L-09`），所以这一步是手输地址。
4. 打开开发者工具 Network 面板——`L-04` / `L-05` 要看请求。

---

## 核心六条（任务卡点名）

- [ ] **L-01 创建 A/B 两个账号**
      空状态文案可读（不是空白页）。建 A（平台随意，显示名「A 号」），再建 B（换一个平台，显示名「B 号」）。
      **看**：两个都出现在列表里；创建后新账号被选中；**没有手动刷新**。

- [ ] **L-02 切换账号不沿用未保存输入**
      选中 A，在人设框里打「半截草稿」，**不保存**，点 B。
      **看**：B 的人设框里是 B 的内容（或空），**一个字符都不来自 A**。再点回 A：A 的框是**服务端的内容**，那半截草稿**已经没了**（这是设计，不是 bug——见 spec User Story 2）。

- [ ] **L-03 刷新保持**
      给 A 写一段人设，保存，看到「已保存」。按 F5。
      **看**：内容还在，且「第 N 版」的版本号与保存后一致。
      **再看**：换一个浏览器（或无痕窗口）登录同一账号，内容仍在——证明它在服务端，不在本地。

- [ ] **L-04 保存三态**
      (a) 正常保存 → 「已保存」。
      (b) **409**：开两个标签页都停在 A 的人设上，几乎同时点两边的保存。至少一次应出现「**有人同时改了这个账号，再保存一次即可**」。
      **看**：这句话里**没有「失败」二字**；再点一次保存能成功。
      (c) **失败**：断网（或在 DevTools 里 offline）后点保存 → 「保存失败」。恢复网络后能再保存。
      > 409 不一定第一次就撞上。撞不出来时，记下「未复现」而不是勾上——这条的价值就在于真见过那句话。

- [ ] **L-05 双账号人设互不影响**
      给 A 连改三次人设（每次都保存），然后看 B。
      **看**：B 的人设内容与版本号**纹丝不动**（B 若从未保存过，仍显示「还没有保存过版本」）。

- [ ] **L-06 插件关闭仍可用**
      把工作区的插件功能关掉，重新进入 `/{workspaceSlug}/accounts`。
      **看**：页面照常打开，创建、编辑平台/显示名、编辑并保存人设**全部可用**。
      > 这条防的是「照抄设置页标签页时把 `PLUGINS_V1_FLAG` 门控一起抄进来」。

## 附加两条（本卡实现引出的）

- [ ] **L-07 空人设是合法的**
      给一个新账号**不填任何人设**直接保存。
      **看**：保存成功并出现版本号（不是「请填写」之类的拦截）。清空一个已有人设再保存也同样成功。

- [ ] **L-08 视觉与原生页一致**
      并排打开 `/{workspaceSlug}/settings`（工作区标签页）与 `/{workspaceSlug}/accounts`，**同一主题、同一缩放、同一字号偏好**。
      **看**：卡片圆角、分隔线、行高、标签列宽度、保存态的图标与字号**一致**；选中的账号在鼠标悬停时**没有被降级成普通 hover 的样子**。
