# 合同：账号资料范围偏好

## 1. 受控集合

| 值 | 含义 |
|---|---|
| `local` | 只用本地已有资料 |
| `web` | 只用联网检索到的资料 |
| `all` | 两者都用（**默认**） |

精确匹配，不 trim、不折叠大小写——理由与平台枚举相同：`"All"` 与 `"all"` 若都接受，就会变成同一个偏好的两种存法。

## 2. 存储

`content_account.settings ->> 'loretide.scope'`。**零迁移。**

- **写时校验**：不在集合内即 400，且存储不变；
- **读时补默认**：响应里总有一个合法值，**存储保持原样**——没存过就是没存过；
- **合并写入**：服务端读-改-写，账号其余 `settings` 键原样保留。

## 3. 端点

| 方法 | 路径 | 成功 | 失败 |
|---|---|---|---|
| PUT | `/api/content-accounts/{id}/scope` | 200 Account（settings 已含 scope） | 400 非法值 / 404 越权或不存在 |

`GET /api/content-accounts` 与 `GET /{id}` 的响应里 `settings` **总是**带 `loretide.scope`（补默认，不回写）。

`PATCH /{id}` 携带的 `settings` 若含非法 `loretide.scope`，同样 400。

## 4. 与诊断快照的分工

| 位置 | 是什么 | 谁写 |
|---|---|---|
| `account.settings['loretide.scope']` | **账号的偏好**：上次选了什么 | 只有本卡的设置接口 |
| `Snapshot.Scope`（`source_scope`） | **这一次运行实际用的范围** | 运行自己 |
| `Snapshot.Preference`（`saved_preference`） | 运行发生时偏好是什么，**记录用** | 运行自己 |

**运行和复现都不写第一行。** 快照侧的「复现不回写」已由 `diagnostics/reproduce_preference_test.go` 守着（D13-V10 / spec 008 G5）；本卡加的是账号侧那一半，且沿用它的手法——用一个夹具永不产生的偏好值，否则「没写」与「写了刚好相同」分不开。

## 5. 不变量

| # | 不变量 |
|---|---|
| A1 | 没存过的账号读作 `all` |
| A2 | 读不产生任何存储变化 |
| A3 | 设置后读到设置的值 |
| A4 | 写入保留其余 `settings` 键 |
| A5 | 非法值 400 + 诊断错误对象，且存储不变 |
| A6 | `PATCH settings` 里的非法值同样被拒 |
| A7 | 改 A 不影响 B |
| A8 | 越权 404，与不存在逐字节相同 |
| A9 | 每次写入记一条审计事件 |
| A10 | 诊断运行与复现不改动账号存储的偏好 |
| A11 | Go 与 core 的受控集合逐值相等 |
| A12 | 存着非法值时读作 `all`，且不顺手改库 |

## 6. 变异验证（三处）

| # | 改动 | 应变红 |
|---|---|---|
| M1 | 读时补默认改成**读时写回** | A2 |
| M2 | `SetScope` 直接写 `{scope}` 而不合并 | A4 |
| M3 | `PATCH` 路径不校验 scope | A6 |
