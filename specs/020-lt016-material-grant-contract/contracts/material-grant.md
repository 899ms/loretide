# 合同：素材与任务授权范围

## 1. 三个形状

```
Principal   { Kind: "task" | "human", ID }
ResourceRef { Workspace, Account, Kind, ID }     // Account 为空 = 品牌级共享
Grant       { Principal, Workspace, Account, Kinds[], ExpiresAt, Revoked }
```

- `Grant.Account` 为空表示**品牌范围**的授权，覆盖该品牌下任意账号的资源；
- `Grant.Kinds` 为空表示**不覆盖任何资源类型**——空不等于全部，否则一份写错的授权会变成最大的那一份；
- `Grant.ExpiresAt` 为零值表示不过期。撤销与过期是两件事，各自独立生效。

## 2. 判定入口

```
CanRead(ctx, recorder, ReadRequest{Principal, Workspace, Resource, Now, Grants}) GrantDecision
```

`Workspace` 是**调用方已经通过 `Authorize` 的那个工作区**。这一层不重做品牌判定，它假定品牌判定已经发生——两层的分工是本合同的第一句话：

| 层 | 问题 | 谁答 |
|---|---|---|
| 品牌 | 这个人能不能在这个品牌里做事？ | `Authorize`（LT-010） |
| 资源 | 这个主体能不能读这一份东西？ | `CanRead`（本卡） |

**`CanRead` 不查任何表。** 归属事实由调用方作为 `ResourceRef` 交上来，正如 `Authorize` 让调用方交 `Membership`。这也是包注释那句「不回答归属」要被改精确的原因：它反对的是**替调用方查表**，不反对**对调用方交来的事实作判定**。

## 3. 判定顺序

1. 主体或资源引用**不完整** → 拒绝（`ReasonIncomplete`）。不猜。
2. `Resource.Workspace != Workspace` → 拒绝（`ReasonWorkspace`）。
3. `Resource.Account == ""`（品牌级共享）→ **允许**，不需要授权。
4. 否则在 `Grants` 里找一份覆盖它的：主体相同、工作区相同、账号覆盖（授权账号为空或相等）、资源类型在 `Kinds` 内、未撤销、未过期。
5. 找到 → 允许。找不到 → 拒绝，理由取**最接近的那一个**：若某份授权各维度都对、只是被撤销或已过期，理由是 `ReasonRevoked` / `ReasonExpired`，而不是笼统的 `ReasonNoGrant`。

**为什么理由要取最接近的**：理由不进响应（响应一律同形），它进技术日志。「你有一份刚好过期的授权」和「你从来没有授权」是两件需要不同处理的事，把它们记成同一个字眼，支持排查时就得重新猜。

## 4. 拒绝的形状

拒绝**与「资源不存在」同形**：`RefusalStatus` / `RefusalBody`，不含资源 id、不含正文、不含归属。理由只出现在技术事件的 `Step` 字段里，与 `Authorize` 的做法一致。

## 5. 缓存：硬要求

**本卡不实现缓存。** 但若将来任何地方缓存判定结果：

> **撤销与过期必须使缓存失效。**

这不是建议。一份被撤销的授权只要还有一个缓存条目认它，撤销就没有发生；而「被撤销的那一刻就出局」正是这一层存在的意义——与 `Authorize` 不缓存成员关系的理由逐字相同。过期同理：过期是时间到了自动发生的撤销，缓存若按写入时刻判定，就会让一份过期授权继续有效到缓存失效为止。

实现缓存的那张卡必须同时交付：撤销时的失效路径、过期的上界不超过最短授权有效期、以及一条「撤销后立刻不可读」的用例。**没有这三样就不要缓存。**

## 6. 提示词不是凭证

人设提示词（LT-012）是账号的**表达配置**，是 `content_account_revision` 里的一个字段的版本历史。两个账号的提示词逐字节相同，只说明它们写得像。

**判定不得读取、比较或派生自提示词或任何账号表达配置。** 用例以两个提示词完全相同的真实账号钉住这一条——放在 handler 包，因为 `workspace-core` 依赖里没有 `ip-profile`，只有在两个模块都可见的地方才能用真账号来测，而不是用一个假设。
