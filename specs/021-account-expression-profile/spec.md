## User Scenarios & Testing *(mandatory)*

### User Story 1 —— 创作者填一部分，确认，留下一个完整版本（P1）

创作者填了受众、内容支柱、主要渠道、每周可投入时间，其余留空。确认。

**验收**
1. 产生**一个** `AccountConfigRevision`，承载**整份档案**——不是每个字段一版；
2. 填了的字段状态是「已确认」，没填的是「待补充」；
3. **没填的字段里没有任何系统写入的内容**——不是空字符串加一句占位文案，是空。

### User Story 2 —— 系统不替创作者猜（P1）

创作者没填「经验与可信依据」。

**验收**
1. 该字段保持空且标「待补充」；
2. 系统**不**从别的字段推断、不填示例、不填「暂无」；
3. 这一条对身份、经历、成绩、商业承诺**四类**各有用例——它们是 §3.1 点名不得猜测的四类。

### User Story 3 —— 改一次就是新一版，旧版原样可读（P1）

创作者改了「禁用表达」，再确认。

**验收**
1. 新版本包含改后的整份档案；
2. 旧版本**逐字节不变**，包括那些这次没动的字段；
3. 旧版本的 `revision_id` 仍可读出旧内容——这是 LT-012 已有的性质，本卡不得破坏它。

### User Story 4 —— 最小可开始条件是一个能算的答案（P1）

系统要能回答「这个账号可以开始了吗」。条件：**受众、内容方向、至少一个渠道、可投入时间**四项齐备。

**验收**
1. 四项齐备 → 可开始；
2. 缺任意一项 → 不可开始，并**说出缺哪几项**（缺的清单，不是一个布尔）；
3. 判定是纯函数，Go 与 core 各一份，有测试比对两边一致；
4. 其余字段（常见问题、经验、定位主张、表达风格、禁用表达、内容目标、风格样本）**不影响**这个判定——它们是内容质量的输入，不是开始的门槛。

### User Story 5 —— 没有风格样本就中性表达，并且说出来（P2）

创作者没贴任何风格样本。

**验收**
1. 档案被标记为「使用中性表达」；
2. 这个标记是**算出来的**（没有样本即为真），不是另一个要人去勾的开关——两份真相会漂移；
3. **不阻止**记录素材或人工写作：这个标记不参与最小可开始条件的判定。

### User Story 6 —— 提炼入口在，但明说暂不可用（P2）

创作者看到「从我的输入提炼候选档案」的位置。

**验收**
1. 该入口存在且**明确标注「暂不可用（执行器禁用，EP-08 接入）」**；
2. 它**不产生任何内容**——不返回假的提炼结果，不填任何字段；
3. 本卡不调任何模型。**（界面部分在第二个 PR；本 PR 只保证接口层不留一个会悄悄返回假数据的洞。）**

### Edge Cases

- 所有字段都空 + 确认 → 合法，产生一版，全部「待补充」，不可开始；
- 字段超长 → 400 诊断错误对象，存储不变；
- 主要渠道填了一个不在受控平台集合里的值 → 400；
- 同一账号并发两次确认 → 沿用 LT-012 的有界重试 / 409，本卡不另造；
- 只改风格样本 → 仍是一个新版本（整份档案一起存）；
- 旧版本（本卡之前写的、只有 `persona_prompt` 的那些）→ 读出来档案为空、全部「待补充」，**不报错**。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：MUST 支持 §3.1 点名的十个字段：受众、常见问题、经验与可信依据、定位主张、内容支柱、表达风格、禁用表达、主要渠道、每周可投入时间、内容目标。
- **FR-002**：MUST 支持**文本形式**的风格样本（粘贴）；文件上传**不在本卡**（W-03，等 Windows）。
- **FR-003**：每个字段 MUST 携带「已确认 / 待补充」状态。
- **FR-004**：空字段 MUST 保持空并标「待补充」；MUST NOT 写入任何系统生成的内容。
- **FR-005**：确认 MUST 产生**一个**承载整份档案的 `AccountConfigRevision`。
- **FR-006**：旧版本 MUST 保持逐字节不变且可读。
- **FR-007**：MUST 提供最小可开始条件的判定，返回**缺失项清单**而不只是布尔。四项为受众、**内容支柱（即 §3.1 的「内容方向」，Q3 裁决）**、至少一个渠道、可投入时间。
- **FR-008**：该判定 MUST 是纯函数，且 Go 与 core 两份 MUST 有测试比对一致。
- **FR-009**：无风格样本时 MUST 标记「中性表达」，且该标记 MUST 是算出来的。
- **FR-010**：「中性表达」标记 MUST NOT 参与最小可开始条件，MUST NOT 阻止任何写入。
- **FR-011**：主要渠道的取值 MUST 来自既有的受控平台集合（`ip-profile` 的 `Platforms`），MUST NOT 另立一份。
- **FR-012**：本卡 MUST NOT 调用任何模型、MUST NOT 产生提炼结果。
- **FR-013**：越权 MUST 经 `workspace-core` 回 404，与不存在无法区分。
- **FR-014**：写入 MUST 经诊断记一条审计事件（沿用 LT-012 的路径）。
- **FR-015**：带路径参数的新端点 MUST 有一条**穿过真实中间件、参数值与上下文值不同**的用例（工作流第 12 步）。
- **FR-016**：本卡 MUST NOT 新增界面，MUST NOT 写 UI 单测。
- **FR-017**：本卡之前写下的旧版本 MUST 可读且不报错。

### Key Entities

- **ExpressionProfile**（新）：十个字段 + 风格样本，每项带值与状态。**是 `Revision` 的一部分，不是独立实体。**
- **Revision**（已有，扩展）：新增 `Profile`。`persona_prompt` 保留为自己的字段——它是 LT-012 的产物，有端点、有页面、有用例，且语义上是「人设提示词」，不是 §3.1 那十项中的任何一项。
- **Readiness**（新，纯计算）：可否开始 + 缺失项清单。**不落库**——它是从档案算出来的，存一份就是第二份真相。

## Assumptions

1. **「Agent 提炼候选档案」本卡不实现。** constitution 原则 IX 下真实执行器禁用；提炼入口留一个明确的「暂不可用（执行器禁用，EP-08 接入）」位，**不伪造提炼结果**。因此「逐项展示提炼依据」这半句在本卡**未交付**，PR 正文的 SOP 对应一节会如实写「未开始」。
2. **风格样本只存文本。** 文件上传属 W-03。
3. **最小可开始条件是可计算的判定**，由 core 纯函数给出供 EP-04 消费；服务端保留同一份判定以便在写入侧也能表达。
4. **不自动猜测身份、经历、成绩、商业承诺**——任何字段为空时系统不填默认内容，只标待补充。这四类各有一条负例。
5. **每周可投入时间**存为一个整数（小时）。§3.1 只说「每周可投入时间」，没说单位；小时是最不容易产生歧义的粒度，且 0 与「未填」要能区分（未填是状态，不是 0）。
6. **不改 LT-012 的并发机制**：确认走同一条有界重试 / 409 路径。

## 澄清问题与裁决（三项均裁决为 A）

### Q1 完整档案存在哪？

- **A（推荐，已暂定）：给 `content_account_revision` 加一列 `profile jsonb`。** 一条 revision 承载整份档案，`persona_prompt` 保留为独立列。理由：「确认即一版、旧版可读」的机制原封不动；字段增减不需要迁移（§3.1 的字段仍在演进）；运行仍然只钉**一个** `revision_id`。代价是 jsonb 里的结构没有数据库层校验——由 Go 受控类型兜底，与 `settings` 的 `loretide.scope` 同样的取舍。
- **B**：另起表 `content_account_profile_revision`。坏处是**两套版本号、两处「当前版本」**，运行要钉两个快照才能复现一次生成——正是 LT-012 花力气避免的那种第二份真相。
- **C**：每个字段一列（10+ 列）。数据库层有类型，但每加一个字段就要一次迁移，而这批字段**还在演进**；且 §3.1 的几项本身是长文本，列化没有换来查询能力。

### Q2 「已确认 / 待补充」怎么存？

- **A（推荐，已暂定）：每个字段是 `{value, status}`。** 状态就在字段旁边，读一个字段就知道它算不算数。空值默认 `pending`。
- **B**：另存一个 `confirmed_fields` 数组。两份真相，且「字段有值但不在数组里」与「在数组里但没值」两种矛盾状态都能表示出来——能表示的矛盾状态迟早会出现。

### Q3 §3.1 的「内容方向」对应哪个字段？

最小可开始条件写的是「受众、**内容方向**、至少一个渠道、可投入时间」，而字段清单里没有一项就叫「内容方向」。

- **A（推荐，已暂定）：`content_pillars`（内容支柱）。** 「打算持续产出哪些方向」与「内容方向」是同一件事，且它在字段清单里紧挨着定位主张，读起来就是那一组里最具体的那个。
- **B**：`positioning`（定位主张）。定位讲的是「我是谁、对谁有用」，比「方向」更靠近身份而不是题材。
- **C**：新增一个独立的 `content_direction` 字段。忠实于原文，但会与内容支柱高度重叠，让创作者填两遍近似的东西。

**这一条尤其需要主任务确认**：判定错了，「可以开始」的门槛就设在了错误的字段上，而这是 EP-04 直接消费的东西。
