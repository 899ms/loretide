# EP-04「开始界面、选题与 SOP」拆分方案

**日期**：2026-09-15 · **基线**：`app-main` @ `5d6d47f` · **决定**：用户 2026-09-15 定 EP-04 不再等 W-03，以**粘贴文本与 URL** 为输入即可开工，依赖本地文件 / 素材包 / 知识卡的半边留空位。

EP-04 是阶段项，任务卡写明须先拆成独立卡。本文件是那份拆分。

## 拆成四张

| 卡 | 名称 | 规模 | 标注 |
|---|---|---|---|
| **EP-04a** | 手工选题卡与冻结简报 | 中（两张表、两组端点、一页） | **web-only 可做** |
| **EP-04b** | 开始界面与输入快照 | 中（无新表，一页 + 一个装配点） | **web-only 可做**，但依赖尚未成文的「最小可开始条件」 |
| **EP-04c** | 候选选题自动生成与每日建议 | 大 | **需等 EP-08 模型**，且**需等 W-03**（知识卡） |
| **EP-04d** | 必用 / 排除接入 | 小到中 | **需等 W-03**（LT-023 检索） |

**为什么是四张而不是三或五**：骨架给的四张各自有独立的验收边界，且切口落在真实的依赖断面上——a 完全不依赖外部能力，b 只依赖 a 与既有偏好，c 同时卡模型与知识卡，d 只卡检索。再细分会切出无法独立验收的半张卡；合并则会让一张卡同时卡两种外部依赖。**骨架照单采纳，两处调整见下。**

## EP-04a 手工选题卡与冻结简报

**依赖**：LT-009（品牌工作区）、LT-010（授权）、LT-013（账号页）——**全部已合入**。不依赖模型、不依赖文件、不依赖知识卡。

**规模**：两张表（选题卡、简报版本）、两组端点、一页界面。按 SOP 阶段规则**先出存储与接口 PR，再出页面 PR**。

**交付**：

- 用户自建选题卡，字段按 `docs/01` §5.2 的七项：写给谁 / 解决什么问题 / 拟表达什么判断、为什么适合这个 IP、为什么是现在、与已有作品的关系、证据缺口与投入、适合哪些渠道、推荐动作。
- 四个动作：**开始 / 收藏 / 暂缓 / 放弃**。暂缓与放弃带快捷原因与自由备注，**作为偏好信号记录，单次操作不改变 IP 定位**。
- 选择「开始」后生成 `ContentBriefRevision`，字段按 §5.3 的十一项：受众、核心问题、主张与边界、渠道、形式、结构、引用要求、资料范围、交付物、时间上限、成本上限。
- 简报**修改生成新版本**，既有运行继续引用它开始时的版本。

**验收**：

1. 七个字段都能填、能存、能读回；没有时效依据时「为什么是现在」可以写成「无时效依据」而不是留空被拒。
2. 四个动作各自改变卡的状态；暂缓 / 放弃记下原因与备注。
3. 「开始」产出一个简报版本，十一个字段齐全。
4. 修改简报**追加新版本**，旧版本仍可读——append-only，任何读改写都不成立。
5. 跨品牌隔离：A 品牌的选题卡与简报在 B 品牌读不到，越权走 workspace-core 的 404。

**标注：web-only 可做。** 输入是用户手打的文本，不调模型、不读文件。

**一条本卡验不了的事，必须写在交付说明里**：§5.3 的「既有运行继续引用它开始时的版本」——**今天没有运行**（`agent-workflow` 未落地），所以这条只能由**结构**保证（版本表 append-only、版本 id 是被引用的键），运行侧的断言要等 agent-workflow。**不能因为结构对了就把这条记成已验收。**

## EP-04b 开始界面与输入快照

**依赖**：EP-04a（选定简报版本）、LT-014（资料范围偏好，已合入 `specs/018`）、**「最小可开始条件」**。

**规模**：无新表。一页界面加一个快照装配点。

**交付**：

- 消费 LT-014 的资料范围偏好（保存上次选择）。
- 校验最小可开始条件。
- 选定简报版本。
- 「开始」后把配置**固定成输入快照**，与 diagnostics 的 `Snapshot` 对齐。
- 非法依赖拒绝；项目可选。

**验收**：缺任一必要条件时「开始」不可点并说明缺什么；开始后快照字段固定，事后改配置不影响已开始的运行；项目留空也能开始。

**标注：web-only 可做**，但有一处**依赖尚未成文**：任务卡把「最小可开始条件」记作 `specs/021`，而**本仓库没有 `specs/021`**（`specs/` 目前到 `020-lt016-material-grant-contract` 为止）。派 EP-04b 之前需要主任务确认那份规格的去向：已在别处、尚未开写、还是并进本卡。**不补齐就无法判断「最小」到底包含哪几项。**

**与 diagnostics `Snapshot` 对齐的现成事实**（`contract.go:51`）：`ConfigVersion` / `PersonaRef` / `SOPVersion` / `SkillVersion` / `RuleVersion` / `Executor` / `ExecutorVersion` / `Scope`(`source_scope`) / `Preference`(`saved_preference`) / `Required` / `Excluded` / `Grants` / `Hashes` / `Temperature` / `Budget` / `Timeout`。`Scope` 与 `Preference` 是**两个独立字段**（`specs/018` 已确认），EP-04b 不要再造第二套。

## EP-04c 候选选题自动生成与每日建议

**依赖**：**EP-08（模型）** 与 **W-03（知识卡、素材包）**。另需近期订阅信号、已有选题与作品、内容支柱覆盖、已确认经营结论、历史反馈——`docs/01` §5.1 的输入清单里，这些多数还没有产出方。

**规模**：大。排序策略本身就是一项独立设计（§5.1 明写「不能把今天发布最多作为唯一目标」，还要覆盖常青、旧作更新、系列续篇、储备选题）。

**交付**：每日建议默认最多 5 个优先候选、可展开备选。

**本阶段做什么**：**只留接口与「暂不可用」位**。界面上有这个区域，状态是明确的「暂不可用」并说明原因，**不是空白、不是加载中、不是伪造的候选**。

**验收**（本阶段）：候选区显示「暂不可用」并说明缺什么；**没有任何伪造候选**；接口形状定下来后 EP-08 接上不需要改调用方。

**标注：需等 EP-08 模型 + 需等 W-03。**

## EP-04d 必用 / 排除接入

**依赖**：**LT-023 检索**（等 W-03）。

**规模**：小到中。选题卡与简报上各加一组「必用 / 排除」的引用，落到简报的「资料范围」字段与快照的 `Required` / `Excluded`。

**交付**：在简报里指定必用与排除的资料，开始时固定进快照。

**验收**：必用项缺失时开始被拒并说明；排除项不出现在本次可用材料里；两者都进快照且事后不可变。

**标注：需等 W-03。** 快照侧的 `Required` / `Excluded` 字段**今天已经存在**，所以这张卡等的是**检索与资料实体**，不是快照结构。

## 对骨架的两处调整

1. **EP-04b 加了一条前置说明**：任务卡引用的 `specs/021`「最小可开始条件」在本仓库不存在。不是删这张卡，是派它之前要把这份规格的去向定下来——否则「最小」包含哪几项没有依据，做出来的校验只能是猜的。
2. **EP-04a 补了一条「本卡验不了」**：§5.3 的「既有运行继续引用旧版」在没有运行的阶段只能由结构保证。写进拆分方案而不是留到实施时才发现，是因为它会影响 EP-04a 的验收怎么写——把它当成已验收，等 agent-workflow 落地时没人会回头补这条断言。

**其余照骨架采纳**：四张卡的边界、名称、各自的交付与依赖均未改动。
