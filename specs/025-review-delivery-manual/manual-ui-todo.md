# 手动 UI 清单（025 review-delivery 审核、交付与发布记录）

页面入口：选题卡详情页 `/{workspaceSlug}/topics` → 选中一张卡 → 展开作品 → 展开文档 → **版本历史之后**的「审核」「交付」「发布记录」三个区块。

**为什么挂在这里，不是三条新路由**：审核的对象是一个**版本**，而版本只在文档编辑区能看到。024 已经把「作品 / 文档 / 编辑 / 历史」做成同一张选题卡详情页上的逐级区块（见 `specs/024/manual-ui-todo.md` 的同一段说明），本卡照此延续。三条新路由需要先决定 `packages/core/paths` 的助手与侧边栏口径，不在本卡范围。

**跨模块怎么接的**：`review-delivery` 的依赖表里没有 `work-editor` 的反向边，也没有 `ip-profile`。所以 work-editor 的 `WorkSections` 上加了一个**可选 render 插槽** `renderArtifactExtras`（它自己的文件，不改登记表），由 web 适配器 `topics/page.tsx` 把 `ReviewDeliverySections` 注入进去；账号列表同样由适配器取好再传进来。

存储与接口由 PR 1（#150）交付，本清单只覆盖页面。全部条目**状态：未执行**——只能由主任务在浏览器逐条验收；本会话不做 computer use，不写 UI 单测（宪法 II）。

## 复用的既有组件（未新增控件、未改样式）

`SettingsSection` / `SettingsCard` / `SettingsRow` / `SettingsSaveState`（`@multica/views/settings/layout`）、`Button` / `Input` / `Textarea` / `Select`（`@multica/ui`）。没有新建任何控件，没有设任何颜色，没有引入日期选择器（计划时间是 `Input`，与仓库其它时间输入一致）。

## 两件本卡在浏览器里验不了的事

1. **「系统绝不会自己发布」** 只能证到「代码里没有那条路径」（PR 1 的四条守卫与检索用例）。浏览器里看到的是「到点什么都没发生」，那是**没观察到**，不是**证明不会**。025-U-20 能做的是把这件事暴露给人，不是证明它。
2. **EP-08 接上之后不必改调用方** 今天无法证明。两个 AI 入口是禁用的占位，它们真正接上时会不会需要改这个页面，只有接的时候才知道。
