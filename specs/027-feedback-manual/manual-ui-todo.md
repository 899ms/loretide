# 手动 UI 清单（027 feedback-learning 人工指标与反馈摘录）

页面入口：选题卡详情页 `/{workspaceSlug}/topics` → 选中一张卡 → 展开作品 → 展开文档 → **025 的「发布记录」与「AI 辅助」之后**的六个区块：「真实结果」「已录的数」「录一个数」「一次粘贴多条」「把人说的话记下来 / 已记的反馈 / AI 复盘」「待补录的反馈」。

另一处入口：今日工作台 `/{workspaceSlug}/today` 的**第五项「待补录的反馈」**——本卡之前它是一块写着「暂不可用」的占位，现在接上了真实数据源。

**为什么挂在这里，不是一条新路由**：指标绑的是**一条发布记录**，而发布记录只在文档编辑区的 025 区块里能看到。024 把「作品 / 文档 / 编辑 / 历史」做成同一张选题卡详情页上的逐级区块，025 把「审核 / 交付 / 发布记录」接在它后面，本卡照此延续。

**跨模块怎么接的**：登记表里 `feedback-learning → review-delivery`，方向是单向的，所以 `review-delivery` 的页面组件不能 import 本模块。做法与 #161 给 `work-editor` 加 `renderArtifactExtras` 完全一样：`ReviewDeliverySections` 上新增一个**可选 render 插槽** `renderPublicationExtras`（它自己的文件，**不改登记表**），由 web 适配器 `topics/page.tsx` 把 `FeedbackLearningSections` 注入进去；发布记录列表由 025 的区块取好之后经插槽传进来，本模块不再发一次同样的请求。

存储与接口由 PR 1（#177）交付，本清单只覆盖页面。全部条目**状态：未执行**——只能由主任务在浏览器逐条验收；本会话不做 computer use，不写 UI 单测（宪法 II）。

## 复用的既有组件（未新增控件、未改样式）

`SettingsSection` / `SettingsCard` / `SettingsRow` / `SettingsSaveState`（`@multica/views/settings/layout`）、`Button` / `Input` / `Textarea` / `Select`（`@multica/ui`）。没有新建任何控件，没有设任何颜色，没有引入日期选择器（采样时间与发生时间是 `Input`，与 025 的发布时间一致）。

「待补录」里当前选中的那一行用**字重**表达（`data-[active=true]:font-semibold`），不是颜色，所以 hover 它不会把选中态视觉降级成普通 hover。

## 本清单最要紧的三条

**U-06 / U-07 / U-16 是这张卡的核心。** 把「平台看不到」记成 0，在任何后续聚合里都是真实的坏数据，而且不一致时没有任何东西会报警。界面上有三处必须看得出「留空 ≠ 0」：表单的说明、提交前的「将存为」预览、列表里的「未知」。三处都验。

## 已知边界（都是本卡范围之外，不是坏了）

- **没有 CSV 文件上传**，只有粘贴文本；证据附件同样等 W-03。
- **待补录列表没有翻页**，按品牌全量返回后页内显示；条目上千时需要单独一张卡。
- **待补录是品牌全量**，不按当前作品过滤——它对应的是工作台第五项那件事，不是「这一篇还缺什么」。
- **AI 复盘只有一个状态位**，没有报告表、没有内容、没有重试入口；§7.1 的其余六个状态本卡不产生。
- **没有任何聚合**：没有「这篇总共多少阅读」，没有跨作品对比，没有趋势。那属于 §10.2 / §10.3。
- **桌面端未接线**（与 `/topics`、`/accounts` 一致，页内展开）。
