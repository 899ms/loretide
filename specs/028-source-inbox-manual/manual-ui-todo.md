## 自动覆盖（不进手验）

`packages/core/content/source-inbox/draft.test.ts`（node 环境）覆盖页面的全部判定：

- `draftProblem` 的六条负例各自点名字段（粘贴文本无正文 / 带链接、链接缺失 / 非法 / 带正文、未知类型）；
- `isWebURL` 接受 http/https，拒绝 `javascript:` / `file:` / `data:` / 无协议 / 空；
- `parseTagInput` 按逗号、全角逗号与空白切分，丢空、去重；
- `draftToRequest` 对两种类型分别只发 `content` 或只发 `url`，并带上 `historical_import`；
- **`duplicateHint` 的 `blocking` 恒为 `false`**，无论找到几条；
- `organizeActions` 永不给出当前状态，**且已归档能回到待整理**；
- `bulkSummary` 分开「成功」与「没成功」并列出后者的 id；空批次报 0 而不是成功；
- `canSubmitDraft` / `canSubmitBulk` 的可用条件。

与 `contract.test.ts` 合计 **45 条**。四语言键齐全：`packages/views/locales/parity.test.ts`（160 条）。typecheck 通过本身也证明每个 `t(($) => $.contentSources.*)` 键在 en schema 上存在。

## 已知边界（本 PR 明确未做）

1. **链接条目没有去重提示**（028-U-12）。去重按 `content_hash`，哈希在快照上，而链接首版不生成快照（0 抓取）。这是「0 抓取」与「按内容哈希去重」两条裁决相乘的结果，规格 Out of Scope 已记，**不是遗漏**。
2. **「合并关联」不做**。§4 说「重复素材先提示合并关联」——本卡只做**提示**那一半，合并是人的决定且会牵动引用关系。页面上没有任何合并入口。
3. **「关联已有来源」不做**（R-011 的第三项）。
4. **不接今日工作台**，由 026 的后续修订决定接入形态。
5. **列表没有翻页**：首版按品牌全量返回后在页内筛选。条目上千时需要翻页或服务端筛选，届时是一张单独的卡。
6. **解析状态列不存在**（裁决 Q3 = A），随解析器那张卡出现。
7. **桌面端未接线**、侧边栏无入口。
